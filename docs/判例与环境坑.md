# 判例与环境坑（按模块，按需查阅）

> 本文承接 `AGENTS.md` 精简出去的**过程性内容**：判例的根因链、实测报错、"为什么不能那样做"的证据。
> **规则本身**在 `AGENTS.md`（铁律 §2 / 环境速查 §4）—— 这里是"为什么"与"怎么发现的"，按模块组织、按需加载。
> 每条都实测过；施工过程的完整试错日志在 git 历史的 `docs/开发计划.md` 旧版本（刀谱索引见现版 §4）。

## 1. Node 与 npm

### 1.1 npm 全局缓存含 root 属主文件 → 一律 EPERM
所有 npm 命令加 `--cache /tmp/npm-cache-$$`。**不要 `sudo chown`**（会污染用户全局环境）。

### 1.2 Node 原生跑 `.ts` 的三条规则
- `package.json` 必须有 `"type": "module"`，否则 `SyntaxError: Cannot use import statement outside a module`。
- 导入 `.ts` 模块必须带扩展名（`from '../db/index.ts'`）—— Node 原生 TS 的解析规则。
- strip-only 模式**不支持构造函数参数属性**：`constructor(msg: string, readonly reason: string)` 报
  `SyntaxError [ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX]: TypeScript parameter property is not supported in strip-only mode`。
  必须写显式字段赋值（见 `QueryRefused`）。**固有约束，会反复遇到。**

## 2. DuckDB

### 2.1 取数 API
`conn.run()` 返回的 `DuckDBMaterializedResult` **只有 `getChunk(i)`，没有 `getRows()`** → 取数必须用 `runAndRead*`。
`JSON.stringify(reader.getRows())` 会因 BigInt 抛 `TypeError` → 用 `getRowsJson()` / `getRowObjectsJson()`。
⚠️ `getRowObjectsJson()` 返回的**已经是解析好的数组**，不是 JSON 字符串——再 `JSON.parse()` 会在空结果时报
`SyntaxError: Unexpected end of JSON input`。

### 2.2 单写者锁与三入口
有跨进程写者时，其它进程**连 `READ_ONLY` 都拿不到锁**。当前设计：单进程独占一个 `.duckdb`、
导入与查询用同进程两个连接（MVCC 让读不被写阻塞）；导入频率每月几次，不需要更复杂方案。
**不要引入第二个常驻进程去开这个库。**
Web / MCP / CLI 三个入口都是「薄壳 + 自己开库」，互斥由锁天然强制；CLI 是短命进程（用完即退），
拿不到锁就明确报错、不许静默失败（`docs/需求与架构.md` §4.4 末）。

### 2.3 `enable_external_access=false` 连 `COPY ... TO` 一起拒
实测报错：`Permission Error: Cannot access file "..." - file system operations are disabled by configuration`。
三条走不通的替代方案（都实测过，别再试）：
- `enable_external_access=false` + `allowed_directories` → `Cannot change allowed_directories when enable_external_access is disabled`
- 开 `lock_configuration` 后再 `SET allowed_directories` → `configuration has been locked`
- 想靠 `allowed_directories` 拦读 → **它不拦截 `read_text`/`read_csv`**，实测能读到 `/etc/passwd`

正确做法：`exportParquet()` 开 `{ enable_external_access: 'true', access_mode: 'READ_ONLY' }` 的短命实例，
`conn.closeSync()` + `inst.closeSync()` 收尾。**连接与实例都只有 `closeSync()`**，写 `await inst.close()`
会得到 `inst.close is not a function`。另一条实测事实：归档后主连接也读不回 Parquet
（`read_parquet` 同样被硬化拒）—— 预期行为。

### 2.4 ★ 归档用的短命只读实例会顺手丢掉主实例的库锁
2026-10-01 由一条新 e2e 断言（"归档文件可被 DuckDB 读回"）挖出的**存在很久的静默失效**，三点都实测过：
- **归档之前**：第二个进程 `db.open()` 报 `Could not set lock on file`（单写者不变式成立）。
- **归档一次之后**：那个只读实例 `closeSync()` 的那一刻，**主实例的锁就没了**——第二进程 `db.open()` 直接成功；
  `CHECKPOINT`、跑空查询都拿不回来，**只有关掉重开主实例能拿回**（所以 `exportParquet()` 的 `finally` 调 `reattach()`）。
- **只读实例是"创建那一刻的快照"**：留着不关能保锁但看不见后来的提交（实测连续三次归档读回 0 行）—— 必须每次新建。

**失败形态**（要能一眼认出）：两个写者同开一个库 → 主实例后续归档全部读到**过期视图** → Parquet
**只有表头、0 行**（960 行的批次实测写成 **222 字节**）而 `archived` 还报 `true`。
所以 `exportParquet()` 带 `verify`：写完在同一实例上 `read_parquet` 数一遍，对不上就抛错、`archived` 置 false。

**推论（比这条本身重要）**：`exportParquet()` 是**跨进程也会改变库状态边界**的操作——
"同进程内、只读、用完即弃"不构成例外，别再照着它推理。
**对照**：`db/compact.ts` 开的是 `:memory:` 实例——不打开库文件，不需要 `reattach()` 也不会丢锁。
**要碰库文件才需要那套舞蹈；不需要碰就别碰。**

### 2.5 事务内读自己的写：`query()` vs `queryWriter()`
DuckDB 的读连接**看不到本事务尚未提交的写**。事务里"数一数自己刚写了多少行"走 `query()` 会数出 0 →
守卫误报，而误报的守卫比没有守卫更糟（人会开始不信它）。`db/index.ts` 的 `queryWriter()` 是唯一出口——
**凡读自己刚写的都必须走它**（`runIngest` 数行、`gen/sync.ts` 桥接名字解析都踩过这一条）。

## 3. Excel（xlsx-populate / exceljs）

### 3.1 xlsx-populate 的两个 API 陷阱
- `Sheet.cell()` **只接受** `"B4"` 或 `(row, col)`。传定义名称会崩在 `addressConverter`（`Sheet.js:123`）。
  定义名称用 **`Workbook.definedName(name)`**：返回**已解析好的 Cell 对象**（可直接 `rowNumber()` / `columnNumber()`），
  名称不存在时返回 `undefined`（不抛错）。
- **`cell.style('numberFormat')` 这个"读"操作有副作用** —— 内部走 `styleSheet().createStyle()`，
  向 `styles.xml` **追加**整套 font/fill/border/xf。实测仅"读" 20 格就把 `styles.xml` 从 **2839B 涨到 7947B**、
  fonts **4→24**、cellXfs **8→28**。正确做法 `readNumberFormat()`：
  直接读 `styleSheet()._cellXfsNode.children[cell._styleId].attributes.numFmtId`，再 `getNumberFormatCode(id)`。

### 3.2 日期格给的是序列号（number），不是 Date 对象
实测 `numFmt = 'yyyy-mm-dd'` 的日期格，`cell.value()` 返回 number、`typeof` 也是 number ——
`v instanceof Date` 这类判断**是死代码**。两个方向都踩过：
- 旧长表路径 `normalizeMonth()` 这么写 → 实际走 `String(46173)`，再配 `^(\d{4})[-/年]?(\d{1,2})` →
  **2026-06 的日期格被读成 `4617-04-01`**（数字看着像年份、格式完全正常，没人会去查）。
- 新接入层 `textAt()` **只认字符串**（有意：数字在类型层面没有出口，铁律 1）→ 日期格读成"没有值"，
  期数列凭空消失，而干跑还报 `ok`（只是坐标空缺）。

**处置**：接入规格声明 `keys: [{ col, as: period, type: date }]`，声明了引擎才把序列号按日期解读。
- **为什么不自动看 `numFmt`**（更"聪明"的做法）：**因为重放**。raw 里只存那个数字
  （实测 `kind=number, raw_value=46174`），**没存"它是日期格"这件事**——靠读 xlsx 格式判断，
  首灌（读 xlsx）与重放（读 raw）会得出**不同的期数**。写成声明，两条路读同一份事实（e2e 第 27 阶段钉着）。
- **只支持 1900 系统，1904 一律拒绝**（两处：打开源文件 + 着陆之前——raw 存得下序列号、存不下日期系统，
  那种 raw 会变成重放陷阱）。同日期两套系统序列号差 **1462 天**（2026-06-01 = 46174 vs 44712），
  拿 1900 基准读 1904 工作簿**静默差 4 年**。xlsx-populate 不给这个标志（三个可疑属性全 `undefined`），
  只能自己读 `xl/workbook.xml` 的 `<workbookPr date1904="1">`（`template.ts` 的 `usesDate1904()`）。
- 序列号 **< 61 一律拒绝**（0/负数/1900 年 1–2 月）：Excel 凭空算进了 1900-02-29，1..59 与 ≥61 基准差一天
  —— 而这里**差一天 = 差一个月**，不猜。"按序列号猜年份"这条路永远不要走（旧路就是这么静默写出 4617 年的）。

### 3.3 exceljs 只许生成测试 fixture（devDependencies）
生产路径禁用：对含批注/图表/图片的真实模板 `readFile` 即崩，写出还会**静默删 8/9 类部件**。
另外 `addConditionalFormatting` 用 `type: 'dataBar'` 会崩，测试里用 `cellIs`。

## 4. HTTP 层

- **流式响应没有 `content-length`**：`fs.createReadStream(...).pipe(res)` 不设该头，
  断言 `headers.get('content-length')` 会拿到 `null` —— 按**实际字节**判（`(await res.arrayBuffer()).byteLength`）。
- **不用 multipart 上传**：为省依赖，上传走**原始二进制 body + `X-Filename` 头**（前端 File API 读成
  ArrayBuffer 直发）；文件名要 `encodeURIComponent`，服务端 `safeName()` 剥掉路径成分。

## 5. 工程判例

### 5.1 测试也会成为 bug 的守卫（B4 = 765345）
`specs/月度保送表.yaml` 声明 `year/month` 却从不引用 —— "2026年6月月报"实际把 **12 个月全加总**
（B4 = 765345，真值 66826），而**错的数字已经写进 `test/e2e.ts` 的断言**、此后一直是绿的：
测试不但没抓住 bug，反而把它锁死了。
推论：断言里的期望值必须来自**独立算法**（直接 SQL 查一遍），不能来自"上一次跑出来的结果"；
发现数字对不上时**先怀疑断言**。（铁律 14；`docs/需求与架构.md` §11.3。）

### 5.2 量纲维欠约束：同量级错数（67283 vs 65198）
`rows: company / cols: period_type` 无指标约束时，那一格返回 **67283**、真值 **65198** ——
同量级、格式正常、人不会怀疑。这就是"解析期挡住欠约束"（铁律 17）的全部理由。
判据细节 `docs/需求与架构.md` §7.2.1。

### 5.3 口径名形近写错：那一格静默变 null（66826 → null）
把「本年累计」写成形近的「本年度累计」：`parseSpec` 放行、`diagnoseSpec` 一条不报，
编译执行后那一格从 **66826 变成 null** —— 写进报送表像"这一项本月没有数"。
接入侧早有 `PERIODTYPE_UNKNOWN` 拦这一类；报表侧 2026-10-01 补上（`spec/lint.ts`，e2e 第 14 阶段）。

### 5.4 接口全绿 ≠ 功能可用：浏览器里才撞得到的三个 bug
R1 交付后 e2e **186 项全绿**，但把人真的会走的路径在浏览器里点一遍，连撞 3 个 e2e 结构上抓不到的 bug：
1. **`UnresolvedName` 丢 `kind` 字段** —— 候选清单由公司/指标两个 Resolver 分别产出，汇总成一个列表后
   就再也分不出谁是谁；`DimDecision.kind` 变 `undefined`，服务端按 `kind|normalized` 查决定表**永远匹配不上**
   —— **点「并入」等于没点**，提交被无限次拦下。*为什么 e2e 没抓到*：断言只查了
   `Array.isArray(staged.unresolved.companies)`，从没把 unresolved 转成 decisions 再提交一次
   （现在补的断言正是端到端复现浏览器那一步）。
2. **点完「并入」提交按钮不变** —— 决定记下了，但 `refresh()` 只重渲染卡片没同步按钮状态
   （修法：`syncCommitButton()`，`renderStage()` 与 `refresh()` 都调）。*e2e 断言在服务端，不经过 DOM。*
3. **并发/连点上传撞 `batchId`** —— 只用 `Date.now()`，同毫秒两个请求生成同一个 id →
   `Duplicate key "batch_id: ..."`（修法：时间戳外加进程内自增序号）。*e2e 断言是串行的，从不并发。*

**推论（比这三条本身重要）**：
- **接口测试覆盖不了 UI 状态机** —— 交付带交互的功能前必须真的走一遍人的路径（浏览器点击），不能只看 e2e 绿。
- **"两个来源的数据汇总成一个列表"时，务必把来源标识带下去** —— 丢掉 `kind` 这种"看起来冗余"的字段，
  代价是下游全部失能，而且**不报错**，只是静默不生效。
- **断言要复现用户动作的完整回路**，而不是只检查中间产物存在。
- **凡有唯一 id 生成的地方，都问一句"同毫秒两次会怎样"**。

### 5.5 DDL 字符串里的反引号 / 行注释吞逗号
- `src/db/schema.ts` 的 `DDL` 用反引号包住 —— SQL 注释里写一个 `` ` `` 会把它**提前闭合**，
  后面的 SQL 被当成 TS 解析，报错 `Expected a semicolon` 而且**指在毫不相干的下一行**（排查花了两轮）。
  想要代码样式就用中文引号，或直接写名字。
- 生成的 DDL 同理（`gen/ddl.ts`）：SQL 行注释到行尾，**逗号必须在注释之前** —— 写成 `-- 注释,`
  会连逗号一起被注释掉，报 `syntax error at or near "name"`。

### 5.6 归档静默失效（裸 `catch {}` 判例，R13）
Parquet 归档曾因裸 `catch {}` **静默失效多轮**而无人察觉。现在 `POST /api/ingest/run` 回传
`archived: boolean`，且写完会在同一个只读实例上读回来数一遍（对不上就判失败）。
铁律 12 的由来；锁层面的完整根因链见 §2.4。

### 5.7 `typeof null === 'object'`（两次）
用 `typeof x === 'object'` 区分联合类型时，`typeof null` 也是 `'object'`：
① CLI 参数解析——`--max-bytes` 缺省返回 `null` 被当 Invocation 返回，`main()` 在 `inv.kind` 上崩；
② 生成器分组写法的角色推断——`keys` 组默认角色写死导致显式 `role: dim_fk` 被自判矛盾。
出现在"用 typeof 区分联合类型"的地方，一定先想一遍 null。

### 5.8 断言条数漂移（231 vs 247）
"改了断言要同步文档条数"在本项目漂过两次；README 一直写着过时的 247 与「231 项断言，15 个阶段」，
纳入自校验的当天又漏一处（"技术选型"表格里那个 231）。现在六处由 e2e 末尾**自校验**盯着
（`AGENTS.md` §3/§6、`docs/需求与架构.md` §11.1、`README.md` 三处）—— 忘了同步，红的是 e2e，不是读者。
