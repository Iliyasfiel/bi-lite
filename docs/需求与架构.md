# bi-lite 需求与架构

## 0. 项目定位

本地、轻量的 BI 引擎，服务于财务与经营数据的模板填表报送。
输入是 Excel 与 YAML 接入规格；输出是按 YAML 报表规格填好的模板 Excel，图表为辅助产物。
新模板主要增加规格与映射，不增加一套执行逻辑或一张模板专属事实表。

## 1. 主要流程

```text
源 Excel → 原始着陆 raw → 接入规格展开 stg → DuckDB 事实表
                                               ↓
空白模板 + 报表规格 → 语义查询 → 结果矩阵 → 填充模板 / 图表
```

人通过 Web 或 CLI 操作；agent 通过 MCP 了解结构、编写规格。
所有入口复用接入、查询、编译与渲染引擎。

## 2. 范围

支持本地 Excel 接入、主数据对齐、口径计算、模板报送、必要的查询与图表。
第二版围绕指标声明与模板复用完善主链路。
不做复杂图表编辑器、定时调度、多租户或外部数仓对接。

## 3. 技术与工作区

Node ≥22.6 原生 TypeScript，零前端框架、零构建步骤。
DuckDB 单文件存储；Parquet 归档；YAML 声明规格；xlsx-populate 填充模板。

`src/` 是引擎与三个入口；`models/` 是模型；`ingest/` 是接入规格；
`specs/` 是报表规格；`templates/` 是空白模板；`skills/` 是 agent 手册。
本地数据在 `data/`，报表输出在 `output/`，可重建示例在 `test/fixtures/`。

## 4. 数据模型

### 4.1 共享维度

主体、指标、期间是基础维度。主体与指标有当前属性与历史侧表，可显式按事实期取历史版本。
接入时先对齐主数据名称；格式差异归一，业务归并由人确认。

### 4.2 窄长事实表

财务事实粒度为：**期数 × 窗口起点 × 主体 × 指标 × 场景 × 币种**，度量为金额。
`fin_month` 为窗口终点，`period_from` 为起点，另保留导入批次。
指标增加通常增加维度成员和事实行，不增加金额列。
合同与业务线等运营事实按业务领域独立成表，共享适用维度。

### 4.3 窗口口径

- 单月：起点与终点同月。
- 本年累计：起点为当年一月，终点为报告月。
- 去年同期累计：落库保存去年窗口，查询按报告期平移对齐。
- 账面累计：起点按模型声明，源值实存，包含审计调整。
- 单月同比：语义层计算，使用单月及去年同期单月，不单独存行。

累计查询取指定期末或按月份分别展示。场景与币种需筛选、分组或显式换算。
默认实际/人民币来自事实表 `queryDefaults`，响应展示实际采用的范围。
换汇按事实窗口终点取月汇率，必须完整且唯一。

### 4.4 存储与生命周期

DuckDB 进程内单写者；Web、CLI、MCP 轮流使用同一库。
首次启动引导空库；已有结构的变化先 `plan`，再由人执行 `apply`。
本地数据、上传、归档、审计与报送输出不进入版本管理。

### 4.5 YAML 模型

`models/*.yml` 是业务结构的声明来源，解析为 IR 后生成 DDL、元数据与语义目录。
支持 dimension、fact、aggregate、bridge；维度和桥接可以声明固定成员。
聚合与桥接派生数据由 `rebuild` 重建；业务指标定义与单位规则是第二版重点。

### 4.6 导入批次

每次落库记录源文件与规格、事实行与批次关联。重复坐标默认拒绝；显式覆盖保留批次记录。
结构变化的应用与数据导入是不同动作。

### 4.7 raw 与 stg

原始文件/单元格着陆保留输入；标准化行保留规格、坐标与转换后的业务字段。
事实与标准化行在同一事务写入。重放从库内原始输入重新展开，与标准化行比较。

## 5. 规格与渲染

### 5.1 接入规格

声明源路径、目标事实表、工作表、锚点、行键、值列、口径与固定维度。
支持长表、宽表与网格；可以跳过派生列、排除合计行，声明日期格与空值处理方式。
流程：静态校验 → 试运行 → 主数据确认 → 事务落库与归档。
保存 YAML 不执行导入。

### 5.2 报表规格

声明模板、目标事实表、参数、工作表与区块；每个区块描述行/列维度、排序、度量与范围。
指标与口径必须确定，参数实际参与过滤。区块可使用坐标或定义名称作为锚点。

#### 5.2.1 派生表达式

规格可声明度量表达式，由本地表达式求值器计算。
业务口径与单位规则优先放入 YAML 声明，模板只负责布局。

### 5.3 渲染器

Excel 渲染从原模板打开，只填指定数据格，保留已有样式、数字格式、合并、公式、批注与图表。
图表渲染消费相同结果矩阵。精细排版由 Excel 等工具完成。

### 5.4 编译

规格经参数替换、维度与事实表解析，编译为 SQL，在本地 DuckDB 执行，返回结果矩阵。
可查询的表、维度与口径来自现有声明及注册表。

### 5.5 诊断

解析、Web 和 MCP 使用相同校验逻辑，返回位置、原因与修改建议。
模板推断生成草稿，每个轴说明来源与依据；推测项由人确认。

## 6. 数据边界

### 6.1 本机执行

源数据、金额、查询与模板填充都在本地引擎执行。引擎不调用 LLM。

### 6.2 人与 agent

Web/CLI 为本机用户返回精确查询值；MCP 只返回元数据、文本标签、数字格标记、坐标、形状与状态。
agent 无 SQL 入口，预览与报表工具不返回金额。受众由入口决定。
语义层的 agent 查询采用分档与明细支持阈值，但不作为 MCP 自由取数工具暴露。

## 7. Agent 入口

### 7.1 工具

MCP 提供目录、指标、源结构、模板结构、规格生成/校验/预览、导入与渲染等十二个工具。
操作字段与接线见 `skills/bi-lite-ingest/`，工具定义以 `src/mcp/tools.ts` 为准。

### 7.2 模板与自然语言

agent 用模板结构与业务意图写 YAML；模板推断给草稿，执行前由人确认范围与主数据。
规格是 agent 与确定性引擎的接口。

## 8. Web 与 CLI

Web 提供导入向导、查询、模板与规格管理、预览与导出；只监听 `127.0.0.1`。
CLI 提供接入、渲染、查询、模型变更、重建、重放、验证、目录与 skill 导出。

## 10. 关键约束

保留模板格式；累计与量纲范围明确；主数据歧义交人处理；派生数据可以重建。
开发验收只保留核心节点，避免扩展成参数穷举与开发过程记录。

## 11. 开发状态

第一版已打通接入、存储、语义查询、模板报送、三个入口与重放。
第二版重点是 YAML 指标定义、单位/符号转换及模板复用，见 `docs/开发计划.md`。
