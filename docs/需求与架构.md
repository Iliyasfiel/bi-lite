# bi-lite 需求与架构

## 0. 项目定位

本地、轻量的 BI 引擎，服务于财务与经营数据的模板填表报送。
接入报表按接入规格进入本地数据库；导出规格定义如何生成导出报表，图表为辅助产物。
新模板主要增加规格与映射，不增加一套执行逻辑或一张模板专属事实表。

### 统一术语

方向统一为“接入 / 导出”，是否承载业务数据统一为“规格 / 报表”。

| 方向 | 规格：无业务数据，描述结构和 YAML 语义 | 报表：按相应规格组织的带业务数据 Excel |
|---|---|---|
| 接入 | 接入规格：如何读取、映射和转换源表数据 | 接入报表：用户选择并交给本地引擎读取的源 Excel |
| 导出 | 导出规格：取数范围、参数、布局、坐标及公式保留规则 | 导出报表：本地引擎取数并填充后生成的 Excel |

规格可以关联无业务数据的 Excel 结构样表；“报表”表示承载业务数据的文件，不是在 YAML 中保存金额。
目标规格制定流程由检查、方向选择、LLM 语义澄清、人工确认和引擎生成组成，不依赖业务数据库；当前实现状态见开发计划。
接入报表执行接入、生成导出报表时使用数据库。
LLM 只处理规格及受控结构；接入报表和导出报表中的业务值由本地引擎处理。
现有文件路径保持兼容：`ingest/` 保存接入规格，`specs/` 保存导出规格，`templates/` 保存关联的空白 Excel，
`data/` 保存接入报表及本地数据库，`output/` 保存导出报表。

## 1. 主要流程

```text
接入报表 + 接入规格 → 原始着陆 raw → 标准化 stg → DuckDB 事实表
                                               ↓
导出规格 + 空白 Excel → 语义查询 → 结果矩阵 → 导出报表 / 图表
```

当前 CLI、Web 与外部 agent/MCP 复用本地执行引擎；CLI 规格制定已形成 spec 单入口，Web 对应流程仍待接入。
先跑通 CLI 的规格制定、接入和导出闭环，再开发 Web 的对应交互。

## 2. 范围

支持本地 Excel 接入、主数据对齐、口径计算、模板报送、必要的查询与图表。
第二版围绕指标声明与模板复用完善主链路。
不做复杂图表编辑器、定时调度、多租户或外部数仓对接。

## 3. 技术与工作区

开发按 `.node-version` 的 Node 基线原生运行 TypeScript，零前端框架；仅打包时转译 JavaScript，安装时不编译。
DuckDB 单文件存储；Parquet 归档；YAML 声明规格；xlsx-populate 填充模板。

`src/` 是引擎与三个入口；`models/` 是模型；`ingest/` 是接入规格；
`specs/` 是导出规格；`templates/` 是规格关联的空白 Excel；`skills/` 是 agent 手册。
本地数据在 `data/`，报表输出在 `output/`，可重建示例在 `test/fixtures/`。

## 4. 数据模型

### 4.1 共享维度

主体、指标、期间是基础维度。主体与指标有当前属性与历史侧表，可显式按事实期取历史版本。
接入时先对齐主数据名称；格式差异归一，业务归并由人确认。

### 4.2 窄长事实表

财务事实粒度为：**期数 × 窗口起点 × 主体 × 指标 × 场景 × 币种**，度量为金额。
`fin_month` 为窗口终点，`period_from` 为起点，另保留导入批次。
指标增加通常增加维度成员和事实行，不增加金额列。
合同与业务线等运营事实按业务领域独立成表，共享适用维度。

### 4.3 窗口口径

- 单月：起点与终点同月。
- 本年累计：起点为当年一月，终点为报告月。
- 去年同期累计：落库保存去年窗口，查询按报告期平移对齐。
- 账面累计：起点按模型声明，源值实存，包含审计调整。
- 单月同比：语义层计算，使用单月及去年同期单月，不单独存行。

累计查询取指定期末或按月份分别展示。场景与币种需筛选、分组或显式换算。
默认实际/人民币来自事实表 `queryDefaults`，响应展示实际采用的范围。
换汇按事实窗口终点取月汇率，必须完整且唯一。

### 4.4 存储与生命周期

DuckDB 进程内单写者；Web 持库时 CLI 通过回环服务转交命名操作，未开 Web 时 CLI 取得工作区锁独立执行。
MCP 目前仍须单独占库。服务退出等待已接收操作完成，再关闭连接并释放运行状态与锁；崩溃后验证遗留进程状态再恢复。
批次归档从主库读取原生数据块，在独立内存实例写出并校验 Parquet；不重开库文件，主库始终禁用外部访问。
首次启动引导空库；已有结构的变化先 `plan`，再由人执行 `apply`。
本地数据、上传、归档、审计与报送输出不进入版本管理。

### 4.5 YAML 模型

`models/*.yml` 是业务结构的声明来源，解析为 IR 后生成 DDL、元数据与语义目录。
支持 dimension、fact、aggregate、bridge；维度和桥接可以声明固定成员。
聚合与桥接派生数据由 `rebuild` 重建；业务指标定义在 `metrics/`，源单位与符号转换由接入规格声明。

### 4.6 指标定义

`metrics/*.yml` 独立声明指标列表：`id`（稳定英文编号）、`name`、`unit`、`category`、
`direction`、`aliases` 与可选 `calculation`。公式只引用同文件或其他文件中已声明的指标编号，
支持四则运算、取余与括号；校验未知引用、重复编号/名称/别名及循环依赖。
每个指标的 `fact` 默认为 `fact_finance`，公式依赖必须来自同一事实表。

正常启动时在事务内同步指标主数据，编号通过既有别名映射关联物理 ID；首次接管存量指标按名称/别名匹配，
不重写事实外键，不删除未声明的旧指标。属性变更使用既有历史侧表；`effectiveFrom` 指定生效日，默认当天。
长运行服务在串行操作开始时重读并校验模型/指标；删除声明不删除主数据，历史别名保留。该同步与结构 `plan/apply` 分开。

基础指标按既有接入流程存储；派生指标不接收源金额、不物化为事实行。
查询和模板复用相同公式，先在相同期间、场景、币种和分组内聚合基础指标，再计算派生值；
派生指标只接受 `sum` 聚合，缺操作数或除零返回空值，汇率检查及 agent 支撑行阈值继续生效。
模板支持“指标行 × 口径列”、“公司行 × 指标列（固定口径）”与“公司行 × 口径列（固定指标）”的派生指标。
公式只在确定性本地引擎中执行，不接收 SQL 或任意代码。指标单位为标准单位，源值换算由接入规格显式声明。

### 4.7 接入批次

每次落库记录源文件与规格、事实行与批次关联。重复坐标默认拒绝；显式覆盖保留批次记录。
结构变化的应用与数据导入是不同动作。

### 4.8 raw 与 stg

接入报表先在独立事务中着陆为 raw_file/raw_source/raw_cell，按内容哈希复用原始单元格；
再按接入规格展开并转换为 stg_fact_rows，与事实、批次和规格/声明快照在业务事务内提交。
业务事务失败可能保留已着陆 raw，但不能留下半批事实。Parquet 归档失败单独报告，不回滚已提交事实。
重放从库内 raw 与批次快照重新展开，与标准化行比较；数据试运行不写入本批 raw/stg/事实。

## 5. 规格与渲染

### 5.1 接入规格

声明源路径、目标事实表、工作表、锚点、行键、值列、口径与固定维度。
支持长表、宽表与网格；可以跳过派生列、排除合计行，声明日期格与空值处理方式。
流程：静态校验 → 试运行 → 主数据确认 → 事务落库与归档。
保存 YAML 不执行导入。

#### 5.1.1 单位与符号转换

`values.transforms` 声明源值转换规则：`fromUnit`、`toUnit`、可选 `sign: preserve / negate`、
`rounding: reject / half-up`。`metrics` 可列出稳定指标编号作为覆盖规则；省略时为区块默认规则，
最多一个默认规则，同一指标不得重复指定。未匹配规则的值保持原样，不根据表头或单元格格式猜单位。
支持元/千元/万元/亿元与比率/%的组内转换，相同单位可用于符号转换，不做币种换算。
目标单位必须匹配指标定义，未声明指标使用事实度量的单位。试运行展示规则、作用指标和单元格计数，不展示金额。

试运行、导入与重放共用展开时的转换函数；raw 保留源值，stg 和事实存转换后的值。
转换使用十进制定点运算，并按目标 DECIMAL 精度校验；默认拒绝额外小数，只有显式 `half-up` 才按绝对值四舍五入。
溢出、无法无损传入当前数值接口或单位不匹配时整批拒绝，空值保持既有 skip/null 行为。
每个新批次同事务保存接入规格、指标元数据和模型目录快照。默认重放使用批次快照与 raw，
不受之后修改 YAML、单位或别名影响；无快照的历史批次仍按传入规格重放，并在结果中标明。

### 5.2 导出规格

声明模板、目标事实表、参数、工作表与区块；每个区块描述行/列维度、排序、度量与范围。
指标与口径必须确定，参数实际参与过滤。区块可使用坐标或定义名称作为锚点。

#### 5.2.1 布局复用

指标身份、标准单位与公式放在 `metrics/`，模板规格只声明坐标、轴与取数范围。
`value.periodType` 为“公司行 × 指标列”固定一个已声明的实存口径，
`value.metric` 为“公司行 × 口径列”固定一个指标编号或名称；均可引用参数。
固定绑定不能与对应轴或过滤重复指定。累计口径仍须钉住报告期，场景/币种规则保持一致。
两种布局与原有“指标行 × 口径列”共用指标聚合函数，先分公司汇总依赖再计算比率。
模板金额/比率的数字格式分别保留；变换布局不复制指标公式、不新增业务事实表。

#### 5.2.2 派生表达式

规格可声明度量表达式，由本地表达式求值器计算。
业务口径与单位规则优先放入 YAML 声明，模板只负责布局。

### 5.3 渲染器

Excel 渲染从原模板打开，只填指定数据格，保留已有样式、数字格式、合并、公式、批注与图表。
图表渲染消费相同结果矩阵。精细排版由 Excel 等工具完成。

### 5.4 编译

规格经参数替换、维度与事实表解析，编译为 SQL，在本地 DuckDB 执行，返回结果矩阵。
可查询的表、维度与口径来自现有声明及注册表。

### 5.5 诊断

解析、Web 和 MCP 使用相同校验逻辑，返回位置、原因与修改建议。
模板推断生成草稿，每个轴说明来源与依据；推测项由人确认。

## 6. 数据边界

### 6.1 本机执行

接入报表的读取、业务值转换、查询和导出报表填充均在本地执行，不调用 LLM。
规格制定服务调用 LLM 辅助澄清语义，随后交给确定性引擎校验与生成规格。

### 6.2 人与 agent

Web/CLI 为本机用户返回精确查询值；MCP 只返回元数据、文本标签、数字格标记、坐标、形状与状态。
agent 无 SQL 入口，预览与报表工具不返回金额。受众由入口决定。
语义层的 agent 查询采用分档与明细支持阈值，但不作为 MCP 自由取数工具暴露。
agent 仅使用空白结构样表。结构读取、推断、agent 预览/渲染前，本地扫描所有工作表（含隐藏页）的单元格；
发现实存数值、缓存值、金额或百分比样式的数字文本，或解析/扫描失败时，拒绝并只返回安全提示，不返回文件标签或错误中的原始内容。
普通标签中的年份、期数等数字可保留；公式常量只作为存在标记。该检查不覆盖图片、批注或嵌入附件，不能撤回已上传文件可能造成的模型接触。

## 7. 共享规格制定引擎：目标与边界

本节描述需要满足的架构契约，不代表全部已交付。当前 spec 入口、任务、候选校验和发布已有实现，
但完整语义读取与两方向真实业务闭环未完成；状态和验收范围以 [开发计划](开发计划.md) 为准。

### 7.1 单入口连续流程

接入规格与导出规格共用一个任务协调器，采用相同的检查、会话、草稿、确认与发布机制。
用户只需从规格制定入口提交待检查 Excel；文件可能含数据，检查失败时停止，不发送给 LLM，也不自动清空数据放行。

```text
提交 Excel → 本地安全检查 → 选择接入 / 导出方向 → LLM 连续对话
                  │                              ↓
                拒绝结束                    草稿校验与业务摘要
                                                  ↓
                                           用户确认当前版本
                                                  ↓
                                           引擎生成并发布规格
```

方向选择放在安全检查通过之后。选择方向只是确定任务类型，不是一次额外的安全授权；
发送内容预览在同一任务内提供。相同文件快照不因方向选择重复上传或重复检查；文件或检查政策变化后重新检查。

安全通过、结构投影或模型连通都不算业务完成。任务必须连续推进到规格生成，或明确结束为拒绝、取消、失败、保留待办。
对话中的“对”“好的”参与语义修订，最终确认须由本地明确操作发出，不由模型工具代替。
正式规格制定入口统一为 `bilite spec <Excel路径>`。路径只在本地解析，安全检查通过后在同一终端内
选择接入/导出方向、完成语义澄清、查看业务摘要和文件差异、明确确认并发布规格。
任务 ID、预期修订号、草稿版本与恢复操作由程序维护，普通用户不需要串接 authoring 子命令。
候选可审阅时主动提供“继续修改 / 查看详情 / 确认保存 / 暂存退出 / 取消”选项，不要求记忆斜杠命令。
确认保存以真实文件发布完成为成功条件；模型回答、静态校验通过或草稿保留均不代表规格已生成。

再次执行同一条命令时，根据当前工作区、文件内容哈希和检查政策查找任务，展示继续或新建选择；
多条任务同时存在时显示方向、时间和摘要供选择。文件内容变化须重新检查，不沿用旧确认。
第一次缺少供应商配置时，在检查通过后于入口内引导本机配置，随后返回原任务，不要求退出另跑 setup。
输入路径先按调用目录解析为绝对路径，再切换业务工作区；选定工作区决定产物位置。
没有可用工作区时在入口内询问是否在当前目录初始化空工作区，不自动安装预设、改全局配置或另建业务目录。

此入口的交付边界是接入/导出规格及其必要声明和空白模板。含数据报表的试运行、入库与生成报表属于
后续本地执行阶段，不能因确认规格而自动执行；成功画面说明产物位置和后续操作。

### 7.2 共享部分与方向规则

| 组件 | 职责 |
|---|---|
| CLI / Web 交互层 | 提交文件、检查状态、选择方向、流式对话、审阅、确认、取消和恢复 |
| 任务协调器 | 管理检查快照、方向、顺序消息、草稿版本与状态；拒绝过期修改；单任务模型运行使用可续租租约 |
| pi 会话适配 | 复用供应商协议，维护受控历史与当前草稿，支持预算和取消 |
| 语义声明服务 | 只读模型/指标 YAML 并生成受控语义快照，不读取数据库实存主数据 |
| 方向规则 | 接入、导出各自的提案结构、校验与规格构建，复用现有引擎函数 |
| 确认发布服务 | 生成实际业务摘要与文件差异，校验人工确认，幂等发布和失败恢复 |
| 本地执行引擎 | 根据已确认规格接入、查询和导出报表；不把业务值交给模型 |

两种方向的区别集中在规格内容，不复制一套对话系统：

| 内容 | 接入规格 | 导出规格 |
|---|---|---|
| 位置映射 | 源工作表、锚点、行键、值列 | 目标工作表、区块、行列、坐标 |
| 业务规则 | 字段映射、期间、单位转换、空值、重复及主数据处理 | 指标、主体范围、期间窗口、聚合、场景/币种、公式保留 |
| 静态验收 | 能按声明解释接入报表并构造标准化行，数值正确性留到本地试运行 | 能按声明编译取数计划并匹配填充区域，实际结果留到本地预览 |
| 产物 | 接入规格 YAML，保存在 ingest/ | 导出规格 YAML，保存在 specs/，关联空白 Excel |

同一任务中可复用已确认语义辅助另一方向，但方向变化须重新验证对应规则，两个规格分别绑定内容版本和人工确认。
不先强制制定导出规格：用户可以只制定接入规格，也可以先制定导出规格。

### 7.3 语义与数据库的边界

规格制定的输入是检查后的结构投影、用户文字、工作区已有 models/ 与 metrics/ 声明。
整个制定过程不加载 DuckDB 驱动、不创建业务数据库、不读取 dim_company/dim_metric，不执行 SQL、主数据同步或结构 apply。
查询编译用于验证导出规格能否表达取数语义，不执行查询。数据库空不空不影响结构读取和语义澄清。

空工作区保持为空，不自动添加财务预设、18期数据或既有业务规格。
必要的模型/指标声明变更随草稿提出，和规格一起展示差异，用户明确确认后才发布；
当前引擎无法表达的口径或计算列为能力缺口，不用未经确认的假设生成“可执行”规格。

制定接入规格时仅处理安全检查通过的无数据结构样表；含数据接入报表的本地试运行是执行阶段，不进入 LLM。
数据执行阶段可以读取数据库主数据做名称解析、冲突检查；这与制定规格的语义声明读取不同。

当前实现由本地读取声明后，把部分元数据预加载到每轮系统上下文；内置模型不执行 CLI 命令。
可见内容包括事实表与字段、关联、单位、期间口径、默认场景/币种及指标身份/别名。
现有指标只提供 hasCalculation 标记，未提供公式正文和依赖明细，也没有按需查询语义的只读工具。

本地候选校验已经使用覆盖后的声明与指标定义；模型上下文的 semantic 字段仍来自已发布工作区，
候选声明主要依赖历史提案回看。引擎能校验公式，不等于模型获得了同一份完整公式语义。
因此，预加载快照只是当前底座，尚不能替代需要设计的完整语义读取契约。

### 7.4 受控上下文和提案

检查从同一文件快照构造结构投影：工作表 ID、允许的标签、坐标、范围、合并区、合法锚点和公式存在标记。
隐藏页参与全表检查，首版模型投影省略并报告数量；不发送文件路径、原文件字节、公式正文或缓存。
上下文显式复制允许字段，不序列化本地附件任务。用户文字不另做模型检测，输入处提示勿粘贴真实财务数据。

LLM 提交有类型的语义/布局提案；本地引擎生成候选草稿、诊断和摘要。提案须能表达复合主体/指标行键、
分离取数列和公式保留位置；不能把旧 inferSpec 的简单布局识别当作所有规格的前置门槛，也不硬编码18期模板。
文件路径和写入范围由本地服务绑定；模型无任意文件、shell、SQL、HTTP、人工确认或数据接入工具。
每轮上下文还应包含对应方向的 YAML 必需结构、通用最小示例，以及模型/指标声明格式；
恢复任务同样携带这些契约，不要求用户提供引擎 schema 或堆栈。示例只说明声明格式，不充当已确认业务口径。
结构校验失败只返回位置、原因和修订提示；未经校验的原始对象不得进入摘要、编译或填充范围分析。
当前类型约束主要覆盖工具参数外壳，规格正文仍是 YAML 字符串；内置文本契约与样例不等于已实现统一语义提案结构。

pi 继续复用已锁定的协议适配器，不引入通用 coding-agent 的全局配置、skills、扩展或 MCP 自动发现。
当前版本、支持的供应商和预算见开发计划；个人端点、密钥与配置方法见 README。

### 7.5 草稿、确认和发布

任务状态为：检查中 → 待选方向 → 对话中 → 待确认 → 生成中 → 完成；另有拒绝、取消、失败和明确保留的待办。
附件 ready 仅为内部检查状态。连续多轮必须维护真实消息和工具回执，不能每次从空消息列表开始。
接入规格和导出规格分别有草稿版本；摘要从实际候选内容生成，不采用模型自述替代实际绑定。

人工确认绑定任务、方向、草稿版本/内容哈希、Excel 快照哈希、检查政策与模型/指标声明指纹。
语义修订、方向更改、文件替换或依赖变化使确认失效；确认后不让 LLM 再重写已批准内容。
校验失败在同一任务内修订；失败保留最近有效草稿，恢复不只依赖聊天总结。

| 位置 | 用途与写入时机 |
|---|---|
| .bilite/authoring/<任务ID>/ | 未发布附件快照、受控对话与候选草稿；不视为正式规格 |
| ingest/、specs/ | 用户确认且最终校验通过后，发布对应方向的规格 YAML |
| templates/ | 成功发布导出规格时保存其空白 Excel；接入规格按需保留结构参考 |
| models/、metrics/ | 只发布明确确认的必要声明变更，不添加测试业务数据 |
| data/、output/ | 后续人工接入报表与导出报表使用，规格制定不产生业务事实或带数据结果 |

取消默认清理未发布副本，用户明确选择保留任务时才保存恢复记录；原始用户文件不改写、不删除。
重试复用任务，不重复生成“已放行模板”。拒绝文件不长期保存字节；删除会话不能撤回已发给供应商的内容。

发布在短文件写锁内重验版本和声明指纹，暂存后提交，成功才报告完成；多文件须有提交记录及恢复机制，
不能把逐个 writeFile 当成原子发布。文件协调不等于数据库操作，网络等待期间不持有文件写锁或业务队列。

### 7.6 待设计的语义读取契约

目标是让模型能够依据完整、可解释、版本一致的声明语义制定规格，同时保持业务库隔离。
除表和指标身份外，还需覆盖公式及依赖、单位、窗口、聚合限制和适用范围；区分已有声明、候选变更、
用户确认和未决业务事项，避免把示例或模型推测当作正式口径。

语义读取、候选校验和人工审阅应引用同一候选语义版本，并明确其相对已发布基线的差异。
工作区声明或草稿变化后，旧语义引用与确认应按同一规则失效，不能让模型拿旧快照解释新候选。

共享语义服务应独立于 CLI/Web 交互和供应商协议；模型按需读取的粒度、返回字段、权限、资源上限、
工具暴露方式及版本绑定尚待设计。是否增加具体工具、如何组织预加载与检索、如何处理长历史，
不在本轮文档整理中预先定稿；也不通过读取业务库、运行 SQL 或调用 CLI 子进程绕过这些设计。

## 8. CLI、Web 与报表执行

### 8.1 先 CLI，后 Web

先在 CLI 跑通两类规格制定和接入/导出报表的完整闭环，通过后再开发 Web 对应页面。
CLI 是终端交互层，Web 是图形交互层，两者调用相同的任务与执行服务；Web 不通过启动 CLI 子进程串接业务。
新规格制定任务不进入当前 DATABASE_INVOCATIONS，不借旧 agent generate 的持库操作包住整段对话。
旧 agent template/generate 的具体限制见开发计划；只能兼容为明确的诊断能力，不以“已检查”替代业务成功。

Web 后续展示文件选择、检查进度、方向选择、对话、差异、版本确认、取消恢复和生成结果；
HTTP 层落实本地认证、Origin/CSRF、版本与重复提交校验，不只靠页面按钮。Web API key 配置后置，复用 CLI 已配供应商。

### 8.2 报表执行与共享数据库

接入执行：用户选接入报表与接入规格 → 本地试运行 → 主数据待办 → 用户确认 → raw/stg/事实落库。
导出执行：用户选导出规格和参数 → 语义编译 → DuckDB 查询/本地计算 → 填充空白 Excel → 导出报表。
模型只参与规格语义，不参与读取接入报表业务值或执行数据库查询。

一个工作区同一时刻只有一个数据库持有进程。当前 Web 持库时 CLI 转交命名操作；没有 Web 时 CLI 持锁独立执行。
握手核对真实工作区、数据库、实例和协议，不能只凭端口或 PID；转交不接受任意 SQL/代码。
获取锁后重查服务状态；操作失败不会阻塞后续队列。写请求保留操作 ID，响应丢失时查询状态，不自动重试接入。
停机拒绝新操作、等待已接收操作完成后释放；遗留状态须验证所有者，不能强杀无关进程。MCP 当前仍须单独占库。

当前人工 CLI 保留 ingest、render、query、plan/apply/rebuild、replay、compact 等确定性操作。
外部 agent/MCP 的接入试运行与执行工具只返回拒绝，由本机用户操作；其行为边界见 skills/bi-lite-ingest/。
内置制定引擎完成替代后再退役旧 agent/skill/MCP，保留关闭助手后的人工主链路。

### 8.3 工作区、分发与维护

bin/bilite.mjs 先定位工作区，再加载业务模块：--workspace > BILITE_WORKSPACE > 向上查找工作区标识；旧目录兼容根目录运行。
init 默认只建立标识与空业务目录；财务预设需显式选择，不复制指标、接入报表或数据库，不覆盖已有文件。
业务文件、相对源路径、输出与默认数据库都相对所选工作区，BILITE_DB 保留显式覆盖；接入报表读取遵守源路径白名单。

开发直接运行带 .ts 导入的 TypeScript；发布包提供 bin/、dist/、受控预设和必要说明，安装时不编译。
安装目录不作为业务数据目录；发布验收用真实 tarball，不用 npm link 代替；个人配置、业务数据和测试产物不打包。
帮助、版本及目标中的规格制定不启动服务或打开库。功能扩展通过 YAML 声明与普通内部模块，不引入外部服务或通用插件框架。

现有 web 命令在前台运行，只监听 127.0.0.1，默认 4319；按需指定端口，页面就绪后打开浏览器。
端口占用明确报错，不悄悄换工作区；浏览器打开失败仍保留服务并给出地址。不引入后台守护或远程访问。
skill 安装为显式、可选的文件副本，记录版本；默认不覆盖，不自动配置 MCP 或修改全局设置。

测试区 reset 属于独立维护能力：标记独立测试区、只读预览、明确确认、持锁清理，保留工作区外供应商配置；
拒绝源码/Git/包目录、未知文件、链接和外部数据库覆盖。不能从普通 Web 路由直接删除正在使用的数据库。
具体可用命令和检查入口见贡献指南，当前交付状态见开发计划。
