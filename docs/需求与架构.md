# bi-lite 需求与架构

## 0. 项目定位

本地、轻量的 BI 引擎，服务于财务与经营数据的模板填表报送。
接入报表按接入规格进入本地数据库；导出规格定义如何生成导出报表，图表为辅助产物。
新模板主要增加规格与映射，不增加一套执行逻辑或一张模板专属事实表。

### 统一术语

方向统一为“接入 / 导出”，是否承载业务数据统一为“规格 / 报表”。

| 方向 | 规格：无业务数据，描述结构和 YAML 语义 | 报表：按相应规格组织的带业务数据 Excel |
|---|---|---|
| 接入 | 接入规格：如何读取、映射和转换源表数据 | 接入报表：用户选择并交给本地引擎读取的源 Excel |
| 导出 | 导出规格：取数范围、参数、布局、坐标及公式保留规则 | 导出报表：本地引擎取数并填充后生成的 Excel |

规格可以关联无业务数据的 Excel 结构样表；“报表”表示承载业务数据的文件，不是在 YAML 中保存金额。
目标流程由用户在 Web 中明确 Excel 语义，程序构造、校验并发布 YAML 规格，全程不使用 LLM。
本地含数据文件可作为配置样例，配置预览不写入业务数据；接入执行和导出取数使用数据库。
本文同时记录目标契约与现有引擎基础，不表示新 Web/profile 能力已经实现；状态见开发计划。
现有文件路径保持兼容：`ingest/` 保存接入规格，`specs/` 保存导出规格，`templates/` 保存关联的空白 Excel，
`data/` 保存接入报表及本地数据库，`output/` 保存导出报表。

## 1. 主要流程

```text
接入报表 + 接入规格 → 原始着陆 raw → 标准化 stg → DuckDB 事实表
                                               ↓
导出规格 + 空白 Excel → 语义查询 → 结果矩阵 → 导出报表 / 图表
```

目标主入口为 Web，分为规格配置和日常调用；CLI 保留启动入口和开发维护功能。
现有 CLI、Web、agent/MCP 代码仍在仓库，按开发计划逐步迁移，不将文档调整视为功能退役。

## 2. 范围

支持本地 Excel 接入、主数据对齐、口径计算、模板报送、必要的查询与图表。
优先服务固定模板的月度报送：先由同时懂业务和技术的用户配置验证，再打磨到业务人员可独立配置及调用。
合同金额属于指标扩展；合同管理不在范围内。不以形式化证明任意 Excel 的通用映射可求解为交付前提。
不做 LLM 制定、复杂图表编辑器、定时调度、多租户或外部数仓对接。

## 3. 技术与工作区

后端按 `.node-version` 的 Node 基线原生运行 TypeScript，导入保留 `.ts`；仅打包时转译 JavaScript，安装时不编译。
新 Web 采用 Vue 3、shadcn-vue 和 Tailwind CSS，由 Vite 构建本地静态资源；不再沿用零前端框架约定。
当前独立原型位于 `prototypes/web-app/`，依赖与构建隔离；现有 `src/web/` 尚未迁移，新前端的正式打包接入待验收。
DuckDB 单文件存储；Parquet 归档；YAML 声明规格；xlsx-populate 填充模板。

`src/` 是引擎与三个入口；`models/` 是模型；`ingest/` 是接入规格；
`specs/` 是导出规格；`templates/` 是规格关联的空白 Excel；`skills/` 是 agent 手册。
本地数据在 `data/`，报表输出在 `output/`，可重建示例在 `test/fixtures/`。

## 4. 本体、语义与数据模型

### 4.0 profile 与本体契约（目标）

profile 承载用户的本体及语义配置，工作区和模板规格绑定 profile。创建时选择并确定本体维度，
创建后不增删或改变维度结构；各维度第一层地位平等。每个维度有用户维护的可接受成员集合及别称，
例如主体集合中的法人主体、指标集合中的营业收入和合同金额。默认 profile 可按现有财务模型预设，
具体业务内容属于用户配置，不能成为引擎硬编码前提；默认预设与现有物理模型的适配需在实现前明确。

默认 profile 使用主体、指标、期数、口径四个维度；默认模板不再包含场景和币种，金额统一按人民币处理。
后续外币作为接入转换配置：明确源币种、汇率及适用期间，换算为人民币后接入，并保留换算依据供重放。
该换算尚待实现，不从源名称猜币种或汇率；现有财务引擎的场景/币种字段继续兼容，本轮不改业务库结构。
默认 profile 的调整只用于新建配置，不原地改变已创建 profile 的维度结构。

值由全部必需本体维度共同锚定。数学上为完整坐标空间到实数空间的稀疏部分函数：每个完整坐标至多一个
当前有效值，不同坐标允许数值相同。空值策略须显式声明，必需维度缺失不能用空值补齐。
当前继续采用窄长表；存储优化不是本轮重点，新增 profile 不等于自动实现任意物理模型。

控股关系、指标公式及换算等属于语义层。程序提供内置关系、计算和转换能力，用户配置业务内容；
只有模板口径明确引用后才参与执行。选择母公司不自动展开子公司或推导合并抵销。
取数口径保存在模板内，不新增独立口径目录；跨模板复用的是本体成员和语义定义。

规格配置允许新增成员、别称和语义，先进入草稿，随规格确认发布；删除成员或修改已有语义须进入本体配置。
被规格、语义或数据引用的成员不能直接删除，可停用并保留历史引用。语义变更检查实际依赖，受影响规格须人工复核，
未受影响规格继续使用；历史批次保留原定义以供重放。名称/别称在同一维度中不得歧义，跨维度允许同名。

迁移后各自独立使用，后续提供“仅 profile”和“完整配置包”（含关联规格与模板）两种导出范围；
迁移功能暂缓，不包含业务数据、本地路径及个人设置，不预设自动同步或合并。

### 4.1 共享维度

本节及 4.2–4.8 记录现有财务引擎基础；profile 泛化尚待实现。主体、指标、期间是当前基础维度。主体与指标有当前属性与历史侧表，可显式按事实期取历史版本。
接入时先对齐主数据名称；格式差异归一，业务归并由人确认。

### 4.2 窄长事实表

财务事实粒度为：**期数 × 窗口起点 × 主体 × 指标 × 场景 × 币种**，度量为金额。
`fin_month` 为窗口终点，`period_from` 为起点，另保留导入批次。
指标增加通常增加维度成员和事实行，不增加金额列。
当前另有业务线等事实表；合同金额可在本体适配时作为指标，不预先要求合同专用表。

### 4.3 窗口口径

- 单月：起点与终点同月。
- 本年累计：起点为当年一月，终点为报告月。
- 去年同期累计：落库保存去年窗口，查询按报告期平移对齐。
- 账面累计：起点按模型声明，源值实存，包含审计调整。
- 单月同比：语义层计算，使用单月及去年同期单月，不单独存行。

累计查询取指定期末或按月份分别展示。场景与币种需筛选、分组或显式换算。
默认实际/人民币来自事实表 `queryDefaults`，响应展示实际采用的范围。
换汇按事实窗口终点取月汇率，必须完整且唯一。

### 4.4 存储与生命周期

DuckDB 进程内单写者；Web 持库时 CLI 通过回环服务转交命名操作，未开 Web 时 CLI 取得工作区锁独立执行。
MCP 目前仍须单独占库。服务退出等待已接收操作完成，再关闭连接并释放运行状态与锁；崩溃后验证遗留进程状态再恢复。
批次归档从主库读取原生数据块，在独立内存实例写出并校验 Parquet；不重开库文件，主库始终禁用外部访问。
首次启动引导空库；已有结构的变化先 `plan`，再由人执行 `apply`。
本地数据、上传、归档、审计与报送输出不进入版本管理。

### 4.5 YAML 模型

`models/*.yml` 是业务结构的声明来源，解析为 IR 后生成 DDL、元数据与语义目录。
支持 dimension、fact、aggregate、bridge；维度和桥接可以声明固定成员。
聚合与桥接派生数据由 `rebuild` 重建；业务指标定义在 `metrics/`，源单位与符号转换由接入规格声明。

### 4.6 指标定义

`metrics/*.yml` 独立声明指标列表：`id`（稳定英文编号）、`name`、`unit`、`category`、
`direction`、`aliases` 与可选 `calculation`。公式只引用同文件或其他文件中已声明的指标编号，
支持四则运算、取余与括号；校验未知引用、重复编号/名称/别名及循环依赖。
每个指标的 `fact` 默认为 `fact_finance`，公式依赖必须来自同一事实表。

正常启动时在事务内同步指标主数据，编号通过既有别名映射关联物理 ID；首次接管存量指标按名称/别名匹配，
不重写事实外键，不删除未声明的旧指标。属性变更使用既有历史侧表；`effectiveFrom` 指定生效日，默认当天。
长运行服务在串行操作开始时重读并校验模型/指标；删除声明不删除主数据，历史别名保留。该同步与结构 `plan/apply` 分开。

基础指标按既有接入流程存储；派生指标不接收源金额、不物化为事实行。
查询和模板复用相同公式，先在相同期间、场景、币种和分组内聚合基础指标，再计算派生值；
派生指标只接受 `sum` 聚合，缺操作数或除零返回空值，汇率检查及 agent 支撑行阈值继续生效。
模板支持“指标行 × 口径列”、“公司行 × 指标列（固定口径）”与“公司行 × 口径列（固定指标）”的派生指标。
公式只在确定性本地引擎中执行，不接收 SQL 或任意代码。指标单位为标准单位，源值换算由接入规格显式声明。

### 4.7 接入批次

每次落库记录源文件与规格、事实行与批次关联。重复坐标默认拒绝；显式覆盖保留批次记录。
结构变化的应用与数据导入是不同动作。

### 4.8 raw 与 stg

接入报表先在独立事务中着陆为 raw_file/raw_source/raw_cell，按内容哈希复用原始单元格；
再按接入规格展开并转换为 stg_fact_rows，与事实、批次和规格/声明快照在业务事务内提交。
业务事务失败可能保留已着陆 raw，但不能留下半批事实。Parquet 归档失败单独报告，不回滚已提交事实。
重放从库内 raw 与批次快照重新展开，与标准化行比较；数据试运行不写入本批 raw/stg/事实。

## 5. 规格与渲染

本节记录现有 YAML 和执行能力；新编辑器在第 7 节规定目标交互，表达缺口须扩展契约后实现，不能只靠界面绕过。

### 5.1 接入规格

声明源路径、目标事实表、工作表、锚点、行键、值列、口径与固定维度。
支持长表、宽表与网格；可以跳过派生列、排除合计行，声明日期格与空值处理方式。
流程：静态校验 → 试运行 → 主数据确认 → 事务落库与归档。
保存 YAML 不执行导入。

#### 5.1.1 单位与符号转换

`values.transforms` 声明源值转换规则：`fromUnit`、`toUnit`、可选 `sign: preserve / negate`、
`rounding: reject / half-up`。`metrics` 可列出稳定指标编号作为覆盖规则；省略时为区块默认规则，
最多一个默认规则，同一指标不得重复指定。未匹配规则的值保持原样，不根据表头或单元格格式猜单位。
支持元/千元/万元/亿元与比率/%的组内转换，相同单位可用于符号转换，不做币种换算。
目标单位必须匹配指标定义，未声明指标使用事实度量的单位。现有试运行展示规则、作用指标和单元格计数；
目标 Web 本地预览可展示源值与转换结果，不沿用 agent 入口的金额隐藏限制。

试运行、导入与重放共用展开时的转换函数；raw 保留源值，stg 和事实存转换后的值。
转换使用十进制定点运算，并按目标 DECIMAL 精度校验；默认拒绝额外小数，只有显式 `half-up` 才按绝对值四舍五入。
溢出、无法无损传入当前数值接口或单位不匹配时整批拒绝，空值保持既有 skip/null 行为。
每个新批次同事务保存接入规格、指标元数据和模型目录快照。默认重放使用批次快照与 raw，
不受之后修改 YAML、单位或别名影响；无快照的历史批次仍按传入规格重放，并在结果中标明。

### 5.2 导出规格

声明模板、目标事实表、参数、工作表与区块；每个区块描述行/列维度、排序、度量与范围。
指标与口径必须确定，参数实际参与过滤。区块可使用坐标或定义名称作为锚点。

#### 5.2.1 布局复用

指标身份、标准单位与公式放在 `metrics/`，模板规格只声明坐标、轴与取数范围。
`value.periodType` 为“公司行 × 指标列”固定一个已声明的实存口径，
`value.metric` 为“公司行 × 口径列”固定一个指标编号或名称；均可引用参数。
固定绑定不能与对应轴或过滤重复指定。累计口径仍须钉住报告期，场景/币种规则保持一致。
两种布局与原有“指标行 × 口径列”共用指标聚合函数，先分公司汇总依赖再计算比率。
模板金额/比率的数字格式分别保留；变换布局不复制指标公式、不新增业务事实表。

#### 5.2.2 派生表达式

规格可声明度量表达式，由本地表达式求值器计算。
业务口径与单位规则优先放入 YAML 声明，模板只负责布局。

### 5.3 渲染器

Excel 渲染从原模板打开，只填指定数据格，保留已有样式、数字格式、合并、公式、批注与图表。
图表渲染消费相同结果矩阵。精细排版由 Excel 等工具完成。

### 5.4 编译

规格经参数替换、维度与事实表解析，编译为 SQL，在本地 DuckDB 执行，返回结果矩阵。
可查询的表、维度与口径来自现有声明及注册表。

### 5.5 诊断

解析、Web 和 MCP 使用相同校验逻辑，返回位置、原因与修改建议。
目标编辑器将诊断定位到工作表、区块及单元格，展示最终语义及来源；不通过推测补齐业务决定。

## 6. 本地数据与执行边界

新配置和调用流程全程本地执行，不调用 LLM。允许用户以含数据 Excel 配置和预览映射，
预览不写业务数据；本体声明发布、接入事务、导出取数是明确区分的操作。
保留文件解析资源上限、路径白名单、本地认证、Origin/CSRF、公式保护及防误覆盖措施。
旧 agent/MCP/LLM 入口尚在，其结构扫描、金额隔离和工具权限在显式退役前继续生效；
本地 Web 能展示金额，不代表可放宽旧模型入口的数据边界。

## 7. Web 可视化规格配置（目标）

### 7.1 配置与调用

配置面向业务人员，首版允许一定操作复杂性；调用面向月度重复操作，流程简洁明确。
接入和导出分别组织配置流程、分别保存规格；共享 Excel 画布、语义目录、表达式、诊断及发布基础设施。
用户明确语义，程序确定性构造 YAML；不要求用户编写 YAML，不求解未表达的隐含业务含义。

```text
配置：选择方向和 Excel → 圈定区块 → 绑定维度与值 → 本地预览/补齐 → 校验 → 确认发布
调用：选择已发布规格和文件 → 集中检查/处理异常 → 确认 → 接入或生成导出报表
```

### 7.2 绑定、完整性与表达式

以列配置和批量操作为主，支持维度来自行内列、表头、指定单元格及固定配置的组合。
优先级为区块默认 → 行列设置 → 单元格例外；行列对同一属性冲突时须明确解决，单元格覆盖持续标记。
点击值格展示全部坐标分量、来源和解析成员，允许单独配置不规则位置。

每个参与处理的值必须具有全部必需维度来源。没有来源是语义配置未完成，须交互补齐；
来源存在但数据为空或非法是数据错误，不静默套用缺省值。期间可配置固定日期或“当前月减若干月”，
试运行求值后在本次确认执行中固定，并展示实际期间。自动期间的时区及跨月重验契约在实现前确定。

受限表达式支持业务计算、文本和日期转换，提供构造及预览，不开放任意代码或 SQL。
表达式原语及类型边界需逐步明确；无法表达的业务规则报告能力缺口。

### 7.3 区域与可变行数

先圈定处理区块，区块外不处理；区块内可屏蔽备注等区域，其余明确标注值、维度、公式或待配置。
忽略表示不读取/不填充并保留内容，与清空待填格分开。导出发布前展示保留、清空和填充范围，
生成模板副本，不改原文件，不将样例金额残留带入输出。

接入支持固定范围与动态行范围。动态范围声明起始行、记录识别列及可选结束标记，扫描到结束标记或
工作表有效内容末尾；完全空白行可跳过，不直接终止；存在映射内容但缺维度的行报错。
合计、说明等通过明确排除规则处理。记录数不固化在规格中，但单次执行设文件/行数等资源上限，超限报错，不截断成功。

合并标签按合并范围读取；普通空白不自动沿用。首版可在指定区块显式启用向下沿用及范围/终止约束。
导出首版按模板既有行列填充，新增目录成员不自动扩行扩列。
结构检查覆盖配置依赖的工作表、表头、锚点和区域；变化时提示受影响位置并要求复核，无关样式变化不阻断。

### 7.4 公式与语义维护

识别模板公式及其位置，让用户确认处理方式，不声称自动理解公式业务含义。
导出可保留原公式，或明确替换为引擎填值；接入可忽略公式格，或读文件保存的计算结果，无可用结果则拦截。
首版不承担 Excel 公式重算，不保证源文件缓存已更新；输出可能须在 Excel 中重算。

成员按名称及别称解析，不自动模糊归并。模糊匹配仅建议候选，用户明确选择新建成员或为已有成员添加别称。
配置界面允许进入本体维护并返回原选区；新增内容及其影响随草稿审阅。

### 7.5 草稿与确认发布

允许保存不完整草稿，列出待补项；只有完整且校验通过的规格才能发布调用。
候选配置、预览、诊断和确认引用同一版本及语义视图；维护配置来源，使 YAML 生成和再次编辑不丢失语义。
现有 YAML 支持范围与往返编辑契约需在实现时明确，不能静默丢弃不支持字段。

发布绑定 profile、方向、草稿版本、Excel 快照及依赖定义；编辑、结构或相关语义变化使旧确认失效。
新增声明与规格一起审阅并提交；保存规格不自动导入业务数据。
复用适用的发布锁、多文件提交记录、恢复及幂等能力；只有文件提交核验成功才报告发布完成。

## 8. Web、CLI 与报表执行

### 8.1 Web 为主的入口分工

Web 承担基础数据看板与快捷查询、profile 创建、本体维护、Excel 配置、草稿审阅发布，以及日常接入和导出。
默认看板按主体、期数、指标和口径筛选，金额按人民币展示，提供指标概览、期间走势、主体对比与完整坐标明细。
各主体分别展示，不因控股关系自动合计；累计按期末展示，不跨期求和；缺数不补零，不混合单位或自动换汇。
可保存常用筛选条件作为查询快捷入口，不新增独立业务口径。正式查询复用本地语义引擎，不向用户开放 SQL。
CLI 目标仅保留启动/工作区入口和开发维护功能；业务人员无需学习命令或手写 YAML。
Web 直接调用共享配置和执行服务，不启动 CLI 子进程串接业务。
HTTP 层落实本地认证、Origin/CSRF、版本、重复提交及确认校验，不只依赖页面按钮。
已有 CLI/LLM/agent 功能的迁移或退役单独实施，本轮文档不删除命令、依赖或运行时检查。

### 8.2 报表执行与共享数据库

接入执行：用户选接入报表与接入规格 → 本地试运行 → 主数据待办 → 用户确认 → raw/stg/事实落库。
导出执行：用户选导出规格和参数 → 语义编译 → DuckDB 查询/本地计算 → 填充空白 Excel → 导出报表。
目标调用先集中检查期间、未知成员、非法数据和重复坐标，用户处理后重新检查，再确认整批导入。
任一关键问题未解决，不写入本批业务事实。同坐标只保留一个当前有效值；重复或重叠先拦截，
告知用户并取得明确确认后才可替换，保留批次记录，不静默求和，不误删范围外数据。

一个工作区同一时刻只有一个数据库持有进程。当前 Web 持库时 CLI 转交命名操作；没有 Web 时 CLI 持锁独立执行。
握手核对真实工作区、数据库、实例和协议，不能只凭端口或 PID；转交不接受任意 SQL/代码。
获取锁后重查服务状态；操作失败不会阻塞后续队列。写请求保留操作 ID，响应丢失时查询状态，不自动重试接入。
停机拒绝新操作、等待已接收操作完成后释放；遗留状态须验证所有者，不能强杀无关进程。MCP 当前仍须单独占库。

当前人工 CLI 保留 ingest、render、query、plan/apply/rebuild、replay、compact 等确定性操作。
外部 agent/MCP 的接入试运行与执行工具只返回拒绝，由本机用户操作；其行为边界见 skills/bi-lite-ingest/。
上述为当前兼容能力；目标 Web 闭环验收后，明确 CLI 维护命令及旧 agent/skill/MCP 的退役范围。

### 8.3 工作区、分发与维护

bin/bilite.mjs 先定位工作区，再加载业务模块：--workspace > BILITE_WORKSPACE > 向上查找工作区标识；旧目录兼容根目录运行。
init 默认只建立标识与空业务目录；财务预设需显式选择，不复制指标、接入报表或数据库，不覆盖已有文件。
业务文件、相对源路径、输出与默认数据库都相对所选工作区，BILITE_DB 保留显式覆盖；接入报表读取遵守源路径白名单。

开发直接运行带 .ts 导入的 TypeScript；发布包提供 bin/、dist/、受控预设和必要说明，安装时不编译。
安装目录不作为业务数据目录；发布验收用真实 tarball，不用 npm link 代替；个人配置、业务数据和测试产物不打包。
帮助和版本不启动服务或打开库。配置预览不写业务数据，声明发布和业务执行分别控制。功能扩展通过 YAML 声明与普通内部模块，不引入外部服务或通用插件框架。

现有 web 命令在前台运行，只监听 127.0.0.1，默认 4319；按需指定端口，页面就绪后打开浏览器。
端口占用明确报错，不悄悄换工作区；浏览器打开失败仍保留服务并给出地址。不引入后台守护或远程访问。
skill 安装为显式、可选的文件副本，记录版本；默认不覆盖，不自动配置 MCP 或修改全局设置。

测试区 reset 属于独立维护能力：CLI 显式标记测试区、只读预览、明确确认后持锁清理，保留工作区外供应商配置；
拒绝源码/Git/包目录、未知文件、链接和外部数据库覆盖。实现位于 src/runtime/reset.ts，安装包包含 reset 命令，
Web 不提供 reset 入口，不能从普通 Web 路由删除正在使用的数据库。
具体可用命令和检查入口见贡献指南，当前交付状态见开发计划。
