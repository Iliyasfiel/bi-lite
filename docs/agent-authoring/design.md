# 内置规格助手：方案与架构设计

状态：实施基线，随本 PR 评审；尚未实现。日期：2026-10-17。

## 1. 摘要

在现有 CLI + Web + 本地确定性引擎上增加内置规格助手。空白模板与业务数据分入口接收，
模板含数据即整体拦截；模板通过检查后提取受控结构，助手通过纯文本对话澄清业务含义，生成规格草稿。
用户审阅业务摘要并确认当前版本后注册规格，真实数据试运行和导入仍由用户在 Web 手动完成。

复用 pi 的对话与供应商接入能力，bi-lite 包装业务任务、配置和权限，不向用户提供通用编码 agent。
文件解析、模型输入构造、草稿修改、确认与注册均由 bi-lite 控制。
本文件是后续实施的唯一方案入口，当前行为仍以 [需求与架构](../需求与架构.md) 为准。
本 PR 保留现有空表止损检查和 MCP 拒绝导入；pi、版本确认与开发 reset 尚未实现。

## 2. 背景、目标与范围

当前 `src/spec/template.ts` 负责结构读取，`src/spec/infer.ts` 推断报表草稿；
`src/mcp/tools.ts` 与 CLI agent 入口已有空表检查。
Web `/api/template/infer` 直接调用推断器，结果主要是 YAML 与推测项；
`/api/specs/save`、`/api/ingest/save` 校验后保存，没有版本化业务确认状态。
这些本地 Web 接口本身不调用 LLM，接入助手时不能直接把现有响应当模型输入。

`textAt()` 和 `lookAtSource()` 可返回任意文本，数值字符串也可能通过；
定义名称、原始公式、格式串、异常信息亦不能直接视为安全元数据。
TypeScript 的 `string` 或没有 `value` 字段的对象，不能证明内容不含数据。
渲染器保留原模板格式与未覆盖内容，直接复用带数据模板还可能把旧数据带进新报表。

目标：

- 财务、运营用户通过业务语言纠错，无需阅读或编辑 YAML。
- 文件始终在本地解析；模型只收到经过投影的布局、业务标签与结构标记。
- 支持报表规格与接入规格两类任务，复用现有解析、校验和执行引擎。
- 用户文字正常发送，不扫描、不脱敏、不调用模型检测；输入框旁常驻一句提示。
- 规格生效必须有绑定版本的人工确认；模型没有导入与任意执行能力。

不包含通用 agent 终端、任意插件/MCP 加载、联网搜索、SQL 工具、自动导入、自动合并抵销、
通用 DLP、恶意本机用户防护或所有平台的操作系统沙箱。
主动向对话输入的数据不属于文件自动投影的保护范围。

## 3. 核心决策与架构

```text
Web 模板入口 / 高级 CLI 本地检查
                |
                v
本地空表检查（含数据即拒绝） -> 不可变模板附件
                |
                v
结构解析 / 区域识别 / 本地人工纠正
                |
                +-> 本地预览（可以显示真实内容，不进入模型会话）
                |
                v
受控结构投影 + 允许的业务目录
                |
                v
Web 纯文本对话 -> 编写任务协调器
                                    |
                        出站上下文构造与校验
                                    |
                                    v
                           pi 运行时 + 供应商适配 -> 模型服务
                                    |
                             澄清 / 修改提案
                                    v
                         草稿版本 + 本地静态校验
                                    |
                       业务摘要 / 差异 / 待解决问题
                                    |
                           人工确认与规格注册
                                    |
                  现有 Web 人工试运行 / 导入 / 预览 / 导出
                                    ^
                                    |
                      数据源独立入口（只进入本地引擎）
```

### 组件与边界

| 组件 | 职责 | 限制 |
|---|---|---|
| 附件管理 | 本地复制、哈希、格式与大小限制、绑定任务与角色 | 模型只见模板 ID，不见路径或文件字节；用户选角色，程序强制边界 |
| 结构投影 | 区分标签、期间、数据区，构造允许的模型视图 | 不返回工作簿对象、任意原文窗口 |
| 编写任务协调器 | 上下文、消息、提案、草稿版本、取消与恢复 | 不把用户聊天解释成执行授权 |
| pi 适配器 | 流式文本、专用工具调用、模型错误与用量 | 无 shell、文件系统、SQL、HTTP、导入或确认工具 |
| 草稿服务 | 结构化修改、静态校验、业务摘要、依赖检查 | 模型输出不直接写入生效目录 |
| 确认与注册服务 | 绑定版本、幂等提交、冲突检查 | 仅人工入口可调用 |
| 现有本地引擎 | 数据读取、接入、计算、填表与导出 | 精确值只供人工本地界面 |

首版在现有本地服务中增加这些模块，通过内部接口隔离依赖；避免另建持库服务。
pi 运行时仅接收构造后的上下文与专用能力，不传数据库连接、原始工作簿或执行凭据。
这是对模型能力的限制，不是对同进程代码、依赖漏洞或本机其他 agent 的 OS 隔离保证。
以后可以把 pi 适配器迁到受限 worker；单独子进程本身不提供文件或网络隔离。

## 4. 附件角色与 Excel 到模型的结构投影

模板和数据源分成两个附件角色。模板进入模板结构识别；数据源只保留在本地，
进入现有 Web 导入流程。不自动切换角色，用户明确选择入口，程序按入口强制边界。
系统在模型请求前强制执行：

| 角色 | 允许的用途 | 模型可见性 |
|---|---|---|
| 空白样表 / 报送模板 | 接入或报表结构识别、模板规则 | 仅允许的结构投影 |
| 数据源 | 试运行、导入与主数据确认 | 不进入模型请求或会话历史 |

模板包含业务数值、疑似数值文本、公式常量/缓存或无法确认安全的内容时，整个附件按现有空表策略拦截，
不选择性删除某些单元格后继续。拦截只返回原因和状态，不返回内容。数据源不做这个检查；
它本来就不进入模型。含数据文件不能通过改标签变成模板；须由用户在本机制作空白样表。
接入规格也根据空白结构样表和用户说明编写，不让模型读取真实数据源。

首版不实现数据模板脱敏或自动清空副本。用户提供空白样表，数据源与模板的本地关联由引擎保管。
模型允许接收坐标、行列计数和已确认的报告期等结构数字，禁止接收业务值。
现有 `blank-only-v1` 会保守拒绝含数字标签；新策略的期间/编号例外必须由本地角色解析与代表验收支撑，
不能在接入 pi 时直接放宽为“所有文本都发送”。策略版本与检查结果随模板记录。

### 提取政策

| 输入内容 | 模型视图 |
|---|---|
| 金额、数量、比例及其文本存储形式 | 不应存在；模板检查失败时不进入模型 |
| 表头、指标、公司名称等业务标签 | 从被识别/人工选择的标签区域提取，保留业务名称，不默认做名称匿名化 |
| 任意位置的业务数值或疑似数值文本 | 整个模板拦截，不局部放行 |
| 期间、年度、单位 | 仅在对应语义位置解析后按固定字段重建；无法确定则留待本地确认 |
| 公式及缓存结果 | 仅给公式存在、合计候选等标记；首版不发送公式正文或字符串常量 |
| 数字格式 | 本地归一为金额/百分比/日期等类型与受支持单位；不发送任意格式串 |
| 定义名称、工作表名 | 仅保留有助于编写的标签与合法本地坐标；外部引用、定义表达式不发送 |
| 图片、批注、嵌入对象、外部链接、文件属性 | 不进入模型视图，不执行或追踪链接 |
| 隐藏页 | 首版不发送；需要时由用户在本地选择，再走同样的投影 |

空表检查覆盖所有工作表（含隐藏页），不是只扫描准备给模型的区域。
“营收 1200 万”等混合文本同样要拦截；无法判断安全时整个模板停止，不发送剩余部分。
图片、批注和嵌入内容首版不解析，不向模型发送，也不能因检查通过而宣称任意文件绝对安全。
模板提取后仅输出明确的布局与标签，不进行公司名称匿名化，不增加对话输入检测。
首次请求前显示可展开的发送内容预览，更换模板或提取政策时重新检查。

附件采用不可变本地副本和内容哈希，绑定提取政策版本；后续读取同一副本。
解析失败、加密文件、超出扫描上限或不支持的结构明确整体停止，不回退为原始内容发送。
初期只承诺已验证的 `.xlsx`，不执行宏；压缩包展开大小、条目数和扫描量须有界。

### 唯一出站契约

模型输入只包含 `Projection`、允许的业务目录、用户文本、草稿业务摘要、受控诊断和已有助手消息。
每个文本标签保留坐标来源，模型不得指定任意文件路径来扩大读取范围。
模型可以按当前附件 ID 与坐标请求更多结构，返回仍经同一投影政策。
诊断仅返回代码、位置、固定说明，不发送解析器原始异常、完整文件路径或原文件片段。
标签与工作表文本视为不可信业务材料，不作为系统指令；即使包含“执行命令”等内容，
也不能改变工具或授权。Web 将助手文字与业务标签按文本安全渲染，不执行模型生成的 HTML/脚本。

构造类型用于收窄接口，运行时 schema 校验用于拒绝越界字段；两者都不能单独保证字符串安全。
内部本地预览 DTO 与模型 DTO 分离，不通过删除几个字段或对象展开把前者变成后者。

## 5. 业务对话与草稿确认

界面由“当前业务理解 + 纯文本对话 + 本地模板预览 + 最终确认”构成。
对话区不接收附件、图片或富文本上传；文件通过独立上传区处理，粘贴文本直接按文字发送。
常驻提示：“对话内容会发送给模型服务，请勿粘贴真实财务数据。”
不做数字密度检查、不弹检测提示、不增加检测模型调用。

Web 提供对话、业务摘要和确认按钮，覆盖日常业务闭环。CLI 文本对话暂缓，避免维护两套交互；
CLI 保留确定性高级操作，后续若有明确无头编写需求再接同一任务协议。
YAML 仅保留为高级查看/导出入口。首版流式展示文本，不做复杂单元格编辑或完整聊天平台。

### 集团合并示例

1. 当前理解显示：“第一行取集团本部，其他三行取 A、B、C。”
2. 用户输入：“第一行是集团合并，不是本部，后面还是三家子公司。”
3. 助手提出修改：“第一行改为集团合并；集团合并数已有源报表，还是需要系统计算？”
4. 用户答：“已有合并报表，直接取数。”
5. 当前理解更新：“集团行使用已编制合并数；A/B/C 使用各自数据；不由三家公司加总。”
6. 若来源尚未绑定，列为待解决项；用户可继续解释或在本地选择来源。
7. 最终业务摘要经人工确认后注册规格，随后转到 Web 人工导入。

不能默认集团合并范围仅为 A/B/C，也不能用主数据别名将“集团合并”映射到“集团本部”。
必须检查当前模型是否能区分二者及其事实粒度；不支持时返回建模缺口并阻止注册。
助手可以形成结构提案，首版不自动修改模型或主数据，不实现合并抵销算法。

### 助手契约与技能注入

内置 pi 后，产品不再通过外部 skill/MCP 与任意宿主 agent 交接。助手行为契约直接注入 pi 会话：

- 产品契约（固定）：附件角色、模板拦截、草稿确认、禁止导入；由 bi-lite 构造，不读取项目或用户文件。
- 领域指南（受控）：口径术语、提问方式、修改提案格式；来自 bi-lite 内置资产，限制长度并随版本更新。
- 任务上下文：当前任务、业务摘要、未决问题；来自任务状态，不是磁盘上的 AGENTS.md。

不加载用户或项目目录中的 `AGENTS.md`、skills、MCP 或扩展作为助手提示来源。
首版不提供用户自定义指南。内置 Markdown 可作为指南资产，但不自动发现磁盘上的 AGENTS.md。
这些提示只约束行为，真正的权限由工具注册与服务层强制；修改提示不会授予导入能力。
内置助手完成替代后，旧 `skills/bi-lite-ingest`、`AGENT-PROMPT` 和 MCP 随外部 agent 入口退役；
实施前仍保留当前止损规则，不提前破坏已安装副本。

### 修改与确认

模型输出是“说明 + 提问 + 结构化修改提案”，协调器校验后原子更新草稿并显示业务差异。
说明的关键取数条目从草稿固定生成，模型负责追问与补充解释，不能用聊天叙述替代实际绑定。
业务摘要至少包含主体、期间、指标、单位、场景、币种、来源/聚合方式和排除规则。
歧义之外的关键取数语义也必须纳入最终审阅，不只检查模型自报的推测项。

闲聊、逐项答复和“对”可以帮助修订草稿，不等于最终注册授权。
人工确认绑定草稿版本、规格内容、附件/投影版本和模型/指标目录指纹；
批准后的修改、目录变化或附件替换使原确认不再适用。
无法执行的关键问题阻止确认；本地来源文件的具体绑定可以延后，但必须在试运行前补齐，
且不能改变已确认的主体、范围与来源含义。

## 6. 状态、存储与接口

### 任务状态

```text
附件已接收 -> 结构待检查 -> 澄清与起草 <-> 待审阅
                                          |
                                   人工确认并注册
                                          |
                                       已注册
```

失败/取消作为操作状态，不覆盖最近一次有效草稿；已注册规格需要修订时产生新草稿。
同一任务的消息与提案按顺序处理；客户端提交预期版本，过期提案与确认请求拒绝。
确认与注册作为一次幂等操作；确认记录绑定内容摘要，文件原子写入后校验。
发生崩溃留下的中间状态，重启时核对内容摘要并完成/回退任务状态，不报告虚假成功。

本地保存：

- `Attachment`：真实路径、内容哈希、文件角色与关联规格，不进入模型历史。
- `Projection`：政策版本、保留结构、来源坐标、遗漏与覆盖范围。
- `AuthoringTask`：任务类型、附件、业务说明、当前草稿版本和问题清单。
- `DraftRevision`：结构化规格、业务摘要、修改依据、校验结果与依赖指纹。
- `Confirmation`：人工入口、确认版本、内容摘要、注册位置和结果。
- `Conversation`：用户主动输入、助手输出、受控工具结果及用量；不包含原始工作簿内容。

任务与对话建议放入工作区 `.bilite/authoring/`，附件放独立本地上传目录，纳入忽略规则。
有效规格仍在 `ingest/`、`specs/`，可审阅草稿可导出到 `drafts/`。
记录不自动提交 Git；删除会话不等于删除已注册规格或撤回已发给模型的内容。

### CLI 能力分层

业务用户以 Web 为主。CLI 继续承担初始化、无头/CI、服务未运行时的独立执行、
模型变更、批量重放、故障恢复和自动化，按四层管理：

| 层 | 命令 | 策略 |
|---|---|---|
| 前门 | `init`、`web`、版本/帮助 | 保留；Web 配置模型、模板、对话、确认、导入和出表 |
| 高级/维护 | `ingest run/dry-run/lint`、`plan/apply/rebuild`、`query`、`render`、`validate`、`replay`、`compact`、`catalog` | 保留；不在 Web 新手流程中推荐，供高级用户与自动化使用 |
| 外部 agent 桥 | `agent look/template/generate/preview/diff`、MCP | 内置助手完成替代后退役；迁移前保持空表检查与拒绝导入 |
| 外部手册 | `skill install/export` | 内置助手替代后退役；不再承诺跨宿主集成 |

CLI、Web 与内置助手是服务层的不同调用方，CLI 不承担隔离职责。
模型只获得固定的结构/提案函数；没有 shell、CLI 执行器、人工 HTTP 凭据或通用文件读取器。
高级人工 CLI 保留精确查询和显式导入能力，不宣称阻止外部 agent 以本机用户身份调用它。

### 接口职责（名称暂定）

| 人工接口 | 效果 |
|---|---|
| 创建任务/添加附件 | 本地接收文件，选择角色与任务；不写业务库、不自动调用模型 |
| 查看/调整结构范围 | 本地预览与结构投影准备 |
| 开始会话/发送文本 | 发送受控上下文并串行产生提案，支持取消 |
| 查看任务 | 当前理解、草稿、问题、版本与诊断 |
| 确认并注册 | 校验当前版本与依赖，写入已确认规格；不执行导入 |

Web 与高级 CLI 复用服务层；业务对话使用 POST 提交消息、SSE 接收事件。
模型专用能力只提供读取当前投影/业务目录、提交草稿提案、静态校验；
不暴露人工确认接口、任意 URL、任意路径、SQL、源数据试运行与渲染结果。
内部工具直接注册受控函数，不接入全部既有 MCP 工具。

人工写接口需要本地会话认证、Origin/CSRF 检查与版本校验；worker 若引入，只获得编写能力令牌，
不能复用现有 CLI 执行转交令牌。回环地址与 CORS 本身不等于授权。
同用户恶意进程仍不在此权限方案的保护范围。

## 7. pi 集成、供应商接入、运行与成本

推荐 pi-agent-core + pi-ai：复用 agent 循环、流式事件和模型适配，业务会话由 bi-lite 管理。
模型工具只接受 JSON schema 约束的业务输入，限工具轮数、上下文大小、超时与单次成本预算。
结构超限时显式提示并按区域分批，不能静默截断；同一附件投影缓存并按需加载。

不使用 pi CLI 的交互 shell；显式注入内置契约与领域指南，
不发现用户 `.pi/`、全局/项目 skills、AGENTS.md、MCP 或扩展。
配置只来自用户显式设置的 bi-lite 模型配置。接入和开关不修改全局 agent 配置。
提供模型服务地址、模型名及凭据引用；密钥留在本机，不进入草稿、聊天、日志或包。
首版验证一个明确服务组合，其他兼容端点不因协议相似就自动宣称支持。

备选 coding-agent SDK 可控制工具与资源，但其默认工厂会加载发现的配置与资源并持久化会话，
需要替换这些默认行为。本业务不需要编码 agent 的资源生态，优先选择底层模块。
包名、精确版本、许可证、Node/打包兼容性在实施前锁定；本设计不安装依赖。

### LLM 供应商接入

可以沿用 pi 的供应商与模型接入能力：环境变量、独立 `auth.json`、独立 `models.json`、
兼容端点和部分 OAuth 由 `ModelRuntime` 管理。bi-lite 包一层配置适配层，不直接要求用户维护 pi 全局目录。
供应商配置使用独立的 bi-lite 用户配置目录，由 CLI/Web 共用，不放业务工作区，不自动共享
`~/.pi/agent`。可显式导入 pi 的供应商配置；不导入其 skills、扩展、MCP 或 shell 命令。
模型配置与凭据使用 pi 支持的数据格式、环境变量及明确配置路径；不重写供应商协议、OAuth 刷新或密钥机制。
API key 只发送给用户配置的供应商，日志/浏览器响应不回传密钥；本地文件限制访问权限且不入 Git。

bi-lite 的薄适配层负责提供供应商、模型、端点、凭据录入/引用、连接测试与默认选择界面，
显示当前请求目标，记录脱敏错误与用量。模型不能修改这些设置或选择未配置的服务；无自动跨供应商回退。
首版支持环境变量/API key 和显式兼容端点，OAuth 复用需在锁定版本验证其登录 UI 与授权范围后再开放。
不执行导入配置里的 `!command`，也不自动加载 provider 扩展；需命令取密钥时由用户先在环境中配置。

`ModelRuntime` 是 pi-coding-agent 的集成能力，并非 agent-core 自带的配置加载器。
推荐先评估 agent-core/pi-ai 与 `ModelRuntime` 的组合，保留供应商兼容而不启用编码工具和资源发现；
若锁定版本不能直接组合，则采用 full-control coding-agent SDK，显式替换工具、资源、设置和会话。
实施前以小验证确定这一封装，业务任务接口与边界保持一致，不自行复制一套认证实现。

模型请求不占数据库事务或串行操作队列：先读取业务目录快照，再等待网络；现有 Web 进程仍保持
原有工作区锁和数据库连接的所有权，不为聊天释放进程锁。网络等待期间允许人工数据库操作。
提交提案与确认时重新检查依赖；复用现有单写者/CLI 服务转交，避免 MCP 或助手另起进程占库。
对话压缩保留已确认事实、当前草稿与未决问题；恢复以持久任务为准，不能只靠模型总结。
失败重试有界，不自动重试确认或导入；浏览器断线可恢复事件与已接受消息，避免重复生成。

## 8. 模板导出与开发 reset

### 空白模板

渲染只使用检查过的空白模板，不用真实数据源作为模板；保留格式与必要公式，不修改原附件，
不把填表结果作为新的模型输入。自动从带数据文件生成空白副本不在本期范围。

### 仅开发阶段的 reset

增加人工 `bilite --workspace <目录> dev reset` 和 Web 开发设置中的“重置测试工作区”，共用 reset 服务。
功能尚未实现；本次设计/提交不执行任何清理。该能力不注册到助手工具，正式上线前整体移除。

重置目标是恢复成未配置业务的空工作区，保留的仅是独立用户目录中的 LLM 供应商/模型/凭据配置，
以及继续定位和初始化所必需的工作区标识。环境变量凭据不受影响；重置后仍可直接选择原供应商。
清除目标工作区的数据库/WAL、raw/stg、批次/归档、源上传、模板、接入/报表规格、业务模型与指标、
主数据/别名、草稿、对话、任务、确认、输出、日志与投影缓存；不保留测试历史或自动备份。
财务预设不隐式重装，用户重新选择；预设发行资产属于安装包，不属于待清理工作区。

只允许已明确标记的独立开发业务工作区。仓库代码、Git、依赖、用户原始外部文件和其他工作区不在范围。
拒绝引擎源码检出目录、根/主目录、越界或符号链接目标，以及指向工作区外的数据库覆盖配置，
不沿引用删除外部文件。清理按管理目录清单执行，遇到未知文件先列出并停止，不用根目录通配删除。

执行前展示当前绝对工作区、保留项与删除清单，人工输入工作区名确认；CLI 非交互必须显式给出
该次工作区和确认值。reset 拒绝与模型请求/导入/导出并发，不强杀未知进程；Web 等待已接收操作完成，
保持排他工作区锁，关闭数据库后清理并重建空目录，再刷新界面。CLI 未开服务时取得同一把锁。
删除中途失败明确报告并允许按清单重试，不把部分清理报告为成功，不输出被删除文件内容或密钥。

开发构建才包含命令、路由和界面；生产构建不注册它们，仅隐藏按钮或加运行开关不算移除。
发布验收验证正式包没有 reset 帮助/命令/路由，且开发验收只在临时副本检查重置与配置保留。

## 9. 迁移、验证与取舍

按依赖分段交付，每段独立验收：

1. 附件角色、模板空表检查与结构投影契约，增加开发 reset 支持反复试用；此阶段保留旧入口。
2. 草稿/业务摘要/版本确认服务：先用确定性提案验证交互与状态，不依赖在线模型。
3. pi 适配器：固定工具与配置，接入流式对话、取消、恢复和用量限制。
4. Web 业务对话与确认、供应商设置；真实导入继续走人工 Web。
5. 外部 agent/skill/MCP 退役、打包与文档收敛；正式上线前移除开发 reset。

复用并完善 `assertBlankWorkbook` 的全附件拦截；不得删掉检查并恢复原样文本输出。
外部通用 agent/MCP/skill 保持空表策略，除非显式升级到同一投影契约；
即使升级，也不能保证外部宿主不会自行读取文件，内置助手的保证不外推到外部 agent。
旧规格继续可用；新编写路径必须确认，人工高级编辑保留且不对旧规格伪造历史确认记录。
开关关闭助手应恢复原有人工 CLI/Web 流程，现有数据与有效规格不迁移。

复用核心 e2e，只补关键代表行为：

- 数据源附件不进入模型请求；含数字、文本金额、公式常量/缓存及隐藏内容的模板被整体拦截。
  通过拦截的模板经模拟模型请求捕获，验证源数据未出站、公司标签与期间保留。
- “集团本部 -> 集团合并”的多轮修改，验证业务摘要、能力缺口与过期确认拒绝。
- 模型请求确认/导入、构造任意路径、解析错误带原文等均被拒绝或转换为受控结果。
- 开发 reset 在临时工作区清空业务状态且保留供应商配置；拒绝越界清理，正式发行无 reset 入口。
- 同工作区 Web 与 CLI 共存不新增占库者，联网对话不阻塞数据库操作队列。

在线模型仅做显式手动烟测；自动验收用适配器替身，不发送真实数据。
引擎改动运行 e2e，CLI/分发改动运行 package:check；不新增穷举或文档字数测试。

代价是需要维护业务对话状态与投影规则；用户必须提供空白样表，首版不支持任意文件自动脱敏。
相比独立通用 agent 或 dsh 插件，本方案减少文件与执行能力暴露，但无法替代依赖审查或 OS 隔离。
仅提示词/skill 方案实现简单，却无法强制文件入口、确认与导入边界，因此不采用。

## 10. 实施前验证点

上述产品方向作为本次 PR 的实施基线。后续实施前以针对性验证确定：

- 首批支持的空白模板版式，以及混合文字区域的本地确认方式。
- 合并主体在现有模型中能否无歧义表示；不足时应补的业务声明范围。
- 首个模型服务组合、凭据配置方式与默认预算。
- pi 的底层循环与供应商运行时组合、正式包排除开发 reset 的构建方式。

架构建议不依赖这些细节全部一次决定：先验证投影契约与业务确认，再接真实模型。
