# 内置规格助手：方案与架构设计

状态：实施基线；附件准备层、源码开发 reset、pi SDK 收口、供应商配置和受控发送 DTO 已实现，
DeepSeek `deepseek-flash` 示例结构在线烟测已通过；Web 对话、草稿确认及后续能力以开发计划为准。
当前交付状态、优先级和验证入口以 [开发计划](../开发计划.md) 为准；
现有引擎能力以 [需求与架构](../需求与架构.md) 为准。

## 1. 产品目标与边界

在本地 BI 引擎上内置规格写作助手，运营、财务人员通过业务文字澄清需求，
审阅可读摘要，不需要编辑 YAML。pi 提供对话循环和供应商接入，bi-lite 管理文件、上下文、
草稿状态与人工授权；用户不获得通用编码 agent。

空白模板和业务数据使用独立入口。模板含数据或无法确认安全时整体拦截，不局部删除后放行；
数据源只进入本地人工试运行和导入。即使用户确认规格，模型也没有导入能力。
对话只接受文字，不扫描、不脱敏、不额外调用模型检测；输入框常驻提示：
“对话内容会发送给模型服务，请勿粘贴真实财务数据。”

不做通用 DLP、恶意本机用户隔离、任意插件生态、SQL/shell 助手、自动合并抵销或任意文件自动脱敏。
公司与指标名称按允许的业务标签保留，不默认匿名化。

## 2. 组件与数据流

```text
空白模板入口 -> 全工作簿本地检查 -> 结构投影 -> 业务任务协调器
                                                  ^        |
                                                  |        v
                                            纯文本对话   pi / 模型服务
                                                           |
                                                      规格修改提案
                                                           v
                                            草稿 / 本地校验 / 业务摘要
                                                           |
                                                     人工确认当前版
                                                           v
                                                        注册规格
                                                           |
数据源独立入口 --------------------------------> 人工试运行 / 导入
                                                           |
                                                  本地预览 / Excel 导出
```

| 组件 | 职责 | 限制 |
|---|---|---|
| 附件服务 | 本地副本、内容哈希、安全检查和结构投影 | 不修改模型/指标；不把安装目录当业务配置来源 |
| 任务协调器 | 消息、上下文、修改提案、版本、取消与恢复 | 聊天答复不产生最终执行授权 |
| pi 适配器 | 流式对话、模型调用和固定工具 | 不持有数据库连接或人工入口凭据 |
| 草稿服务 | 复用解析/校验、生成业务摘要与差异 | 未确认内容不写入生效目录 |
| 确认注册服务 | 版本/依赖核对、幂等注册 | 仅人工入口调用；不执行数据导入 |
| 现有 BI 引擎 | 接入、主数据、计算、预览、填表与归档 | 精确业务值只供本地人工流程 |

CLI 与 Web 直接调用共享服务函数，CLI 本身不是隔离边界。
模型只获得明确注册的结构/提案能力，没有 CLI 执行器、任意路径、URL 或 SQL 入口。
同进程模块边界不构成 OS 沙箱；未来迁到 worker 时仍需另行限制文件和网络权限。

## 3. 模板检查与结构投影

附件端接收字节后，从同一内存快照检查并构造投影，保存本地副本、哈希、政策版本与任务记录。
检查覆盖隐藏页和非展示区域。解析失败、含数据和结构超限分别返回受控状态；
内部故障不冒充“含数据”，原始解析异常不返回模型。

结构投影和业务推断分开：布局、坐标、允许的标签可在未注册公司或指标时提取，
不以目录匹配作为安全前提。未知业务含义留给后续澄清。
业务推断继续复用定义名称、findHeader、readRegion、inferSpec 与现有校验，不另写固定列数识别器。

| 内容 | 模型可见性 |
|---|---|
| 实存数值（含零）、缓存值和金额/百分比样式的数字文本 | 模板整体拒绝；不发送数值样例或分布 |
| 允许的表头、公司、指标标签 | 保留文本与来源坐标 |
| 公式 | 允许公式常量；仅存在标记，不发送正文或缓存 |
| 工作表布局与合法本地锚点 | 发送范围、合并区与坐标；不发送任意定义表达式 |
| 工作表名与定义名称中的疑似数值 | 省略名称，使用结构 ID；坐标中的数字仍可发送 |
| 隐藏页 | 全部参与安全检查，首版投影省略并报告数量 |
| 图片、批注、嵌入对象、链接、文件属性 | 不进入模型 DTO，不执行外部引用 |
| 本地文件名、路径、原文件字节、任务管理字段 | 仅本地附件记录，不自动成为模型输入 |

普通标签中的年份、期数等数字可以保留；金额或百分比样式的独立数字文本仍整体拒绝。
图片等未发送载体不等于已完成全文件语义审查。
初期仅支持已验证的 .xlsx，输入、扫描和上下文体积有界；超限明确停止或请求拆分，不静默截断。

类型定义用于收窄接口，不能证明任意字符串安全。模型出站必须显式选择投影 DTO，
不能将整个本地任务对象、Web 精确预览响应、YAML 路径或解析器异常拼进提示。
首个模型请求前显示可展开的发送内容预览；模板变化后重新检查。

## 4. 业务对话、草稿和确认

Web 显示当前业务理解、纯文本对话、本地模板结构及最终确认；YAML 仅作为高级查看/导出。
首版不维护 CLI 聊天，CLI 保留初始化、确定性执行、无头自动化和维护能力。

以“集团合并误识别为集团本部”为例：

1. 页面显示当前取数理解，用户直接说明“第一行是集团合并，后面是 A/B/C 单体”。
2. 助手追问合并数来自已编制报表还是需要计算，不能默认合并范围只有 A/B/C。
3. 用户说明使用既有合并报表；草稿更新主体和来源，不将三个子公司直接加总。
4. 系统检查现有模型能否区分合并主体与本部。若不足，列出建模缺口，阻止注册。
5. 用户审阅完整业务摘要，确认具体版本后注册；源数据绑定和导入走人工本地流程。

模型返回说明、提问和结构化修改提案。协调器校验后更新草稿，展示差异；
关键取数摘要由草稿固定生成，助手解释不能替代实际绑定。
摘要至少含主体/合并范围、期间、指标、单位、场景、币种、来源/聚合方式和排除规则。
所有关键取数语义都纳入审阅，不仅检查模型自报的不确定项。

最终人工确认绑定规格内容、草稿版本、模板哈希、投影政策与模型/指标目录指纹；
内容或依赖变化使确认失效。日常聊天中的“对”可帮助修订，不等于最终注册。
本地文件的具体路径可在执行前绑定，但不能借绑定改变已确认的主体与口径。

```text
附件已检查 -> 澄清与起草 <-> 待审阅 -> 人工确认并注册 -> 已注册
```

失败/取消保留最近有效草稿。单任务按顺序接收消息与提案，提交预期版本，拒绝过期修改。
确认注册须幂等、原子写入，崩溃恢复核对内容哈希；已注册内容的修订产生新草稿。
当前附件任务的 ready 只表示结构检查通过，不代表业务语义或规格已确认。

## 5. pi 与供应商接入

当前锁定 `pi-agent-core`/`pi-ai` 1.3.0（MIT，Node >=22.19.0），采用 Agent、显式 Models 集合
与官方 `openai-completions` 协议适配器。离线验收使用受控 fetch，验证请求中的工具声明、
输出上限、超时与重试配置；受控投影上下文与供应商配置已接入服务层。
DeepSeek `deepseek-flash` 示例结构在线烟测已通过，Web 请求仍待接入。
接入或升级按目标版本的官方文档、随包类型和示例核对接口；只有未定义的行为才使用有界探针。
若该组合存在已确认的能力缺口，再评估 full-control coding-agent SDK，显式替换工具、资源、设置和会话。
ModelRuntime 属于 coding-agent 集成层，不是 agent-core 自带的配置加载器。
不自行复制一套供应商协议、认证或 OAuth 刷新实现。

适配契约：启动前取消不发请求，运行中取消桥接 `Agent.abort()` 并在结束时移除监听；
助手答复从助手消息事件取得，工具错误读取工具结束事件顶层 `isError`。
工具回执不充当助手答复，轮数耗尽保留最后一次助手停止原因。
默认预算为 120 秒超时、最多 1 次重试、重试等待上限 5 秒、输出上限 8192 token、
最多 6 个模型轮次和 24000 字符提示上限；预算在 Agent 到供应商适配器之间显式传递。
新增契约或版本差异只保留稳定结论与对应验收入口，不记录终端试错过程。

bi-lite 提供薄配置界面，复用 pi 的供应商、模型、凭据格式及兼容端点能力。
配置位于独立用户目录，CLI/Web 共用；不放业务工作区，不自动读取 ~/.pi/agent。
允许显式导入供应商数据，不导入 skills、MCP、扩展或 !command。
首版验收环境变量/API key 和一个明确服务组合，OAuth 在锁定版本验证登录流程与权限后开放。
密钥只送明确配置的服务，日志/浏览器响应不回显；不自动切换未知供应商。

当前配置为独立 JSON 文件，默认位于用户配置目录的 `bilite/authoring.json`，
可用 `BILITE_AUTHORING_CONFIG` 指定测试文件。字段为 `version`、`api`、`baseUrl`、
`modelId`、`apiKeyEnv`；`api` 首批只接受 `openai-completions`，
`apiKeyEnv` 必须以 `BILITE_AUTHORING_` 开头，默认变量为 `BILITE_AUTHORING_API_KEY`。
配置不接受 skills、MCP、扩展、命令等额外字段，
基址必须为 HTTPS，本机回环端点可使用 HTTP。

```json
{
  "version": 1,
  "api": "openai-completions",
  "baseUrl": "https://api.deepseek.com/v1",
  "modelId": "deepseek-flash",
  "apiKeyEnv": "BILITE_AUTHORING_API_KEY"
}
```

配置文件只保存端点和密钥变量名，不保存密钥。
`bilite authoring setup` 默认写入 DeepSeek 端点和 `deepseek-flash`，交互输入 API key；
密钥保存到同目录的 `authoring-auth.json`（0600），可用 `BILITE_AUTHORING_AUTH` 指定测试文件。
运行时先读取 `apiKeyEnv` 指定的环境变量，未设置时再读取凭据文件。
`bilite authoring status` 只报告配置、密钥来源和就绪状态，不发起网络请求，也不回显密钥。
首版不读取 `~/.pi/agent`，也不复用 pi 的全局认证文件。

`src/authoring/context.ts` 生成发送预览与实际请求输入：只复制投影中的工作表、单元格标签、
公式存在标记和锚点，以及用户文字；不复制附件路径、文件名、文件字节或缓存值。
发送预览尚未接入 Web 页面。

源码手动烟测只发送示例结构，不读取业务文件：

```bash
bilite authoring test
bilite authoring test --send
```

默认只输出发送预览，不发起网络请求；`--send` 必须显式指定。未设置
`BILITE_AUTHORING_CONFIG` 时读取用户配置目录的 `bilite/authoring.json`。
也可以继续用 `BILITE_AUTHORING_API_KEY` 临时覆盖已保存的密钥。
当前已验证组合为 DeepSeek `deepseek-flash`，烟测只使用示例结构。

产品契约、领域指南、任务状态由 bi-lite 显式注入，不发现项目/全局 AGENTS.md、skills、扩展或 MCP。
提示只能约束行为，真实权限由工具注册和服务层决定。
工具首批仅允许读取投影/业务目录、提交草稿提案和静态校验；不提供确认、导入或真实数据查询工具。
工具轮数、输出、上下文、超时与成本有界，同一投影可缓存；自动化用替身验证出站边界，
真实模型烟测只用用户明确选择的供应商和假数据。

模型网络等待不占数据库事务或串行操作队列。Web 仍持有工作区进程锁；
提交提案和确认时重新核对目录依赖，不另起进程占同一个数据库。
恢复以持久任务和草稿为准，不能只依赖模型压缩后的聊天总结；重试有界，确认/导入不自动重试。

## 6. 存储、入口与授权

当前本地附件任务保存在 .bilite/authoring/，原文件和本地路径不进入模型 DTO。
后续在同一任务边界管理草稿、对话、问题、依赖指纹与人工确认。
有效规格仍在 ingest/、specs/，草稿可在 drafts/ 导出；任务/日志/数据不入 Git。
删除本地会话不会撤回已发送内容，也不隐式删除有效规格或历史批次。

| 入口 | 当前或目标职责 |
|---|---|
| Web 业务入口 | 模板、文字澄清、业务摘要与最终确认，以及人工导入/出表 |
| 人工 CLI | init/web、ingest/query/render、plan/apply/rebuild/replay/validate/compact/catalog |
| 外部 agent/skill/MCP | 当前保持止损；内置助手完成替代后退役 |
| 内部模型工具 | 受控结构和提案，不复用全部既有 MCP 工具 |

业务对话用 POST 消息和 SSE 事件。人工写接口需本地认证、Origin/CSRF 和版本校验，
回环地址本身不是授权。worker 若引入，只得到编写能力，不复用人工 CLI 的执行令牌。
同用户恶意进程不在本方案的权限保证范围。

## 7. 开发 reset 与分发

当前只交付源码命令：先 dev enable 标记独立测试工作区；dev reset 只读预览；
dev reset --confirm <工作区名> 清理并重建业务目录。
清理模型、指标、规格、模板、草稿、数据库/raw/stg/归档、输出及受管会话/缓存/日志。
保留工作区标识和工作区外的供应商配置；不自动重装财务预设、不备份测试历史。

拒绝源码/包/Git/主目录、未知文件、链接和工作区外数据库覆盖。执行前先校验完整清单，
取得现有工作区锁后再次核对清单；活动 Web 或其他持锁者会使 reset 失败。
不删除 db.lock、lock.guard、service.json，不强杀进程、不沿链接清理外部原文件。
删除失败不报告成功；可重新预览后重试。测试仅在临时工作区操作。

开发实现放 dev/，测试放 test/，正式 dist 与安装包不包含它们；设置环境变量也不能启用成品包 reset。
Web reset 入口暂缓，接入时须独立维护操作：停止接收新业务、排空已接收操作、关闭数据库、持锁清理、
重新初始化并刷新界面。不得作为 db.refresh 后的普通路由删除数据库。
正式上线前移除源码开发 reset，不能仅隐藏按钮。

## 8. 取舍、迁移与验收

保留本地引擎和人工高级 CLI，内置助手逐步替代外部宿主交接；不迁移业务数据库。
关闭助手应仍可走原有人工流程。首版不自动修改模型/主数据，不从带数据模板派生空白副本。
代价是用户必须提供空白样表，并在取数规则不明确时参与澄清。

核心验收覆盖：含数据模板整批拒绝；四列与未注册标签不依赖安装包业务配置；
投影无路径/原始公式；过期草稿不能确认；模型无法导入；reset 持锁且拒绝越界；
正式包没有开发入口；Web 与 CLI 共存遵守单写者。
在线模型验证限明确授权的假数据烟测，常规验收不发送真实数据。
