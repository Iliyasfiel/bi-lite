# 18期经营测试

当前测试配置使用5个主体、6个指标，数据覆盖202501至202606共18期。源表共有540条“主体×期间×指标”记录。
原需求中的2025010按202501处理。所有金额与业务数据均为生成的假数据。
源表期间用文本 `2025-01` 至 `2026-06` 表示，语义对应202501至202606，避免读取库将纯数字文本误转成数字。

## 文件与启动

- 源文件：`data/testing/经营测试数据_202501-202606.xlsx`，金额单位万元，比率用百分数（例如57.77表示57.77%）。
- 空白模板：`templates/18期经营报送模板.xlsx`，金额单位元，比率用百分数。
- 接入规格：`ingest/18期经营测试.yaml`。
- 报送规格：`specs/18期经营报送.yaml`，默认报告期202606，上月取数为202605。
- 指标定义：`metrics/finance.yml`，已切换为本次指定的6个指标。自动验收继续使用独立的 `test/config/metrics`，不会覆盖本测试配置。

本机数据库是否已有导入以实际状态为准；源 Excel 不会因保存接入规格而自动入库。
新克隆先按 [贡献指南](../CONTRIBUTING.md) 配置环境，再运行 `npm run fixtures:business` 从版本化假数据快照恢复工作源。
准备命令不创建或清空数据库，也不覆盖已修改的本地源文件。

```bash
npm run fixtures:business
node src/cli.ts ingest dry-run ingest/18期经营测试.yaml
node src/cli.ts ingest run ingest/18期经营测试.yaml
node src/cli.ts render specs/18期经营报送.yaml --out 202606经营报送.xlsx
```

也可以使用项目 skill：`$bi-lite-ingest 按 docs/18期经营测试.md 接入测试源并生成202606经营报送表`。
已有数据导入后再次导入同一源会被拒绝。仅试运行不写事实。

## 数据口径

- 主体：集团公司（合并）、集团公司（本部）、子公司A、子公司B、子公司C。
- 指标：营业总收入、利润总额、经营性现金流量净额、资产负债率、净资产收益率、新签收入合同金额。
- 本年累计：收入、利润、现金流及合同金额按自然年累加；资产负债率取期末余额计算；净资产收益率使用本年净利润与年初/期末平均净资产计算。
- 本月累计：本月发生额。资产负债率仍为期末余额比率；净资产收益率使用本月净利润与月初/月末平均净资产计算。
- 去年同期累计：2026年1至6月对应2025年同期累计。2025年无2024年基础，因此留空，不编造同比基数。
- 同比增长率：`(本年累计-去年同期累计)/ABS(去年同期累计)`。
- 环比增长率：`(本月累计-上月发生额)/ABS(上月发生额)`。202501无202412基础，因此留空。
- 增长率缺基数或分母为0时留空；两个比率指标的增长率是相对变化，不是百分点差。

核验明细中保留资产、负债、净资产、净利润和分红，满足资产=负债+净资产，以及期末净资产=期初净资产+净利润-分红。
集团合并收入、利润及合同扣除合并抵销，合并现金流净额为四家主体净额之和；资产负债按投资、往来和未实现利润抵销。
合并主体不得再与本部及三个子公司加总。两个财务比率都根据合并后的余额和利润重新计算，不加总个体比率。

## 接入与报送

源表保留本年累计、去年同期累计、同比增长率、本月累计、环比增长率五种展示口径。
接入只写本年累计和本月累计；去年同期由已导入的2025年窗口取数，增长率不落金额事实。
两个一月的本年累计与本月累计完全相同，会按相同窗口去重：预计1080个标准化值格、1020条事实。
金额从万元转元，两个比率保持百分数精度。2026年上半年有180组同比基础，除首期外共有510组环比基础。

模板的同比/环比列是 Excel 公式，主引擎填入本年、去年同期和本月发生额，“上月取数”工作表补上环比基数。
在 Excel 打开导出文件后重算公式。Web 预览展示引擎填充区，不执行模板公式，因此不会单独预览增长率列。
更换报告月份时，`year/month` 和 `previousYear/previousMonth` 必须一并调整，尤其注意跨年月份。
2025年报表的去年同期区块无数据，首期的上月区块无数据，增长率应保持空白。
