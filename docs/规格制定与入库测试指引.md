# 规格制定与入库测试指引

使用交互终端，通过 `bilite spec <Excel路径>` 从无数据结构样表制定规格，再由本机用户执行报表入库或导出。
制定过程只访问结构与 YAML 声明；“确认保存”只发布文件，不打开业务数据库、不自动 apply 或入库。
本文是待完成闭环的验收步骤，不是已通过记录。离线关键节点已有验收；真实供应商虽已多轮对话，
两方向从制定到确认保存、业务执行的整体流程仍未通过，完整语义读取也尚待设计。
当前用例卡在语义或候选能力时，应保留任务并记录缺口，不要求用户补引擎 schema、复制 YAML 或绕过校验落盘。

## 1. 选择工作区和样表

可使用已有独立测试区；不要 reset、清空或覆盖已有业务文件。以下假定已安装 CLI：

```bash
export BI_TEST="/path/to/test-workspace"
bilite() { /path/to/installed/bilite --workspace "$BI_TEST" "$@"; }
```

全新工作区才运行 `bilite init "$BI_TEST"`，默认不安装预设。18期验收材料按
[18期经营测试](18期经营测试.md) 显式准备；不用已有手写 YAML 冒充本轮新生成的规格。
源报表含假金额，只能由本地执行引擎读取。接入方向需另备同结构无数据样表，保留工作表名、
表头、行标签、锚点与公式位置；清除实存数值和金额文本后另存，不能修改源报表放行。
导出方向选择无数据报送模板。含数据或损坏的文件应在本地被拒绝，拒绝时不调用模型。

## 2. 同一入口制定并确认保存

```bash
bilite spec "$BI_TEST/data/testing/接入结构样表.xlsx"
```

在入口选择“制定接入规格”，缺少供应商配置时按提示输入；密钥保存在工作区外本机配置目录。
连续说明主体/合并范围、复合主体与指标行、期间、场景、币种、单位及跳过列。
18期接入源的 A/B/C 列分别为主体、期间、指标，D:L 为口径列，F/G/I 为跳过列；
它与导出报送模板的几何不同，不能将导出模板直接当作同结构的接入样表。以实际选择的源表为准。
不要粘贴真实金额。校验失败就在同一对话修订，无需记录任务 ID、修订号或复制 YAML。

候选可审阅时入口展示业务摘要、未决项、正式目标路径及新增/覆盖/删除差异。
核对万元转元、比率不重复换算、期间窗口、跳过列和配套声明；有错误或未决项不能保存。
通过“查看详情”检查最终 YAML 与声明差异；需要调整选择“继续修改”，普通对话中的“好的”不会发布。
选择“确认保存”，只有文件提交及哈希核验完成才应看到“规格已保存”。记录显示的正式文件位置。

暂存、EOF 或失败后再次运行同一命令，选择继续原任务。Ctrl-C 中止请求后按提示保留或清理；
保留时不发布，清理只删除未发布任务副本。发布中断先恢复；若 Web 正在持锁，停止本人服务或稍后重试，
不要删锁或杀未知进程。已完成任务可查看结果，需修订时明确新建。

导出方向使用同样入口：

```bash
bilite spec "$BI_TEST/templates/18期经营报送模板.xlsx"
```

选择“制定导出规格”，核对主体范围、本年/去年同期/本月/上月基数、参数、填充区及公式保留区。
确认后应同时保存 `specs/` 的 YAML、`templates/` 的空白 Excel 与必要声明，无需逐文件落盘。

## 3. 人工试运行、入库与重放

将下方规格路径替换为保存结果中的路径，源报表选择稳定的 `data/` 相对路径：

```bash
bilite ingest lint ingest/generated-ingest.yaml
bilite plan --check
bilite apply
bilite ingest dry-run ingest/generated-ingest.yaml --source data/testing/经营测试数据_202501-202606.xlsx
bilite ingest run ingest/generated-ingest.yaml --source data/testing/经营测试数据_202501-202606.xlsx --strict
bilite replay ingest/generated-ingest.yaml
```

`apply` 是人工执行结构变更；`dry-run` 读取本地报表但不写本批事实，`run` 才正式入库。
出现 `UNMATCHED_MASTER` 时由本机用户确认新建或并入已有主体，不能让模型代替业务归并。
18期样例预期候选值格1080、去重后事实行1020；万元金额转元，两个比率保持百分数精度，
同月本年累计与本月累计按窗口去重。既有18期样例对两个比率使用相对增长率；
若新任务确认使用百分点差，属于另一套口径，需要核对规格、公式及预期，不能沿用旧样例验收结论。
实际规则与期望冲突时先定位声明和执行差异，不强行凑数。

`replay` 应返回 `ok: true`；重复接入应被重复坐标检查拒绝，不用重试绕过。

## 4. 导出与最终核验

```bash
bilite render specs/generated-export.yaml --help
```

按规格中的完整参数组使用 `render` 或 Web 人工预览、导出；跨年和首期缺基数时成组调整期间参数。
核对本年、去年同期、本月及上月数据；集团合并不能与本部/子公司叠加，无基数留空，
不能将两个期末比率相加当合并比率。核验指定填充区、样式、合并和增长率公式；
Web 预览不代表 Excel 公式已重算，需在 Excel 中确认。
