# 开发状态与计划

需求、术语和目标架构见 [需求与架构](需求与架构.md)；当前可用命令见 [README](../README.md)，
环境及验证入口见 [CONTRIBUTING](../CONTRIBUTING.md)。本文记录交付状态，不将目标设计写成已实现能力。

## 1. 方向与当前状态

**新方向已确定：无 LLM 的 Web 可视化配置和日常调用，保留 YAML 确定性执行引擎。新闭环尚未实现或验收。**
用户负责明确 Excel 到本体的语义，程序提供批量绑定、完整性检查、预览和发布；不再以通用自动求解或形式化证明为交付前提。
CLI 目标保留启动入口与开发维护功能，不再要求先完成 CLI 规格制定后开发 Web。

| 范围 | 现有基础 | 新方向缺口 |
|---|---|---|
| 执行引擎 | 长表/宽表/网格接入、主数据、raw/stg/事实、快照重放、查询和模板导出 | 可配置本体与逐格绑定的适配；不能假定当前二维轴规格覆盖全部需求 |
| 声明与语义 | models/、metrics/、公式、单位与窗口规则 | profile、创建后固定维度结构、平等维度及其可扩展成员集合；用户维护关系与语义 |
| Web | 现有人工接入/导出页面；独立 Vue + shadcn-vue 原型 `prototypes/web-app/` 含数据看板、日常报送、规格列表与配置器、本体维护、操作记录 | 看板筛选、趋势/主体对比和常用查询使用内置演示值；正式查询引擎、Excel 上传、语义版本及发布接入待实现 |
| 草稿与发布 | 旧 authoring 有候选校验、版本、确认、发布锁和恢复 | 去除模型对话依赖，适配可视化草稿；新增成员/别称/语义随规格发布 |
| CLI 与旧助手 | CLI spec、pi 会话、agent/MCP/skill 及对应检查仍存在 | 目标入口迁移和旧能力退役尚未实施，不继续扩展供应商/对话主线 |
| 分发与维护 | tarball、工作区定位、CLI reset 等既有实现 | 新 Web 入口的真实安装包验收；不扩大既有平台结论 |

旧助手曾有真实模型尝试和离线验收，不代表新流程已交付。此次方向调整不删除其依赖和安全检查。
README、旧人工指引仍描述现有能力，随对应功能交付更新；新验收不以供应商连通为条件。

## 2. 交付顺序

| 顺序 | 交付范围 | 完成条件 |
|---|---|---|
| 1 | profile、本体及配置契约 | 明确 profile 标识与绑定、默认预设、维度创建后不可改结构、成员/别称/语义定义和存储适配；确定当前 YAML 表达缺口及受限表达式范围 |
| 2 | Web 接入规格配置 | 选样例、圈区块、列为主的组合绑定和单元格例外、动态行范围、逐格解释、缺失/冲突诊断、本地含数据预览、草稿和确认发布形成闭环 |
| 3 | Web 月度接入调用 | 使用发布规格集中检查；未知名称给候选但由用户决定；数据错误和重复先拦截，处理后确认整批入库；快照和重放保持一致 |
| 4 | Web 给定模板导出配置及调用 | 明确坐标及模板内取数口径；公式确认、保留/清空/填值预览；固定布局生成报表并核对 |
| 4a | 基础看板与快捷查询接入 | 在本地语义引擎上实现主体、期数、指标等筛选，核对累计窗口、缺数和单位；概览、趋势、主体对比与明细一致，不自动合计主体 |
| 5 | 下一期复用、维护与分发 | 下一期文件可复用规格；结构变化可定位；语义变更按实际依赖要求复核；Web 权限和真实安装包通过相关验收，明确 CLI/旧助手退役范围 |

成员、别称与语义的新增在规格草稿中维护并随发布确认；删除成员和修改已有语义进入本体配置。
被引用成员不得直接删除，可停用；受影响规格人工复核，不受影响规格继续使用。
profile 的业务内容由用户维护，架构只提供规则能力；主体关系不自动触发汇总。
新设计及原型的默认 profile/模板已收敛为主体、指标、期数、口径四维，金额按人民币；正式 profile 及存量模板迁移尚未实现。
原型不再要求场景、币种选择或绑定。
外币接入换算及其汇率/重放契约后续实现；现有财务库兼容字段未改，不原地迁移旧 profile。
实现步骤可细分，但不在目录/版本契约未明确前堆积界面，亦不要求做完全部配置器后才验证真实模板。

## 3. 首版业务验收

以用户选定的月度快报接入模板和一份真实报送模板，完成：

1. 在 Web 配置完整维度来源及值来源，维护所需成员、别称和语义，预览并发布接入规格。
2. 选择实际文件，集中处理异常及重叠，经确认入库并验证重放。
3. 配置并发布独立导出规格，明确主体范围、指标、期间窗口、单位、计算及公式处理，生成并核对报表。
4. 使用下一期文件验证复用；检查可变行数、日期缺省、结构变化和配置例外不会静默漏数或错配。

配置先由同时懂业务和技术的用户验证，逐步打磨到同事可独立配置；日常调用从首版即要求简洁明确。
既有 [18期经营测试](18期经营测试.md) 可作显式选用的语义参照，不将手写 YAML 当作新界面配置成果。
核对数值、完整坐标、单位、累计窗口、主体汇总、公式保护及跨年期间；涉及 Excel 公式时明确需重算的限制。

## 4. 延后与实施前待定项

- 延后 profile/完整配置包迁移；保留两种导出范围的设计，复制后独立使用，暂不实现同步或合并。
- 延后动态导出扩行扩列、一键标准报表扩展及存储优化；合同仅覆盖金额指标，不做合同管理。
- 不开展任意 Excel 隐含语义自动求解、LLM 接入或任意代码执行。
- 实施前明确四维默认 profile 与现有模型的兼容、YAML 往返编辑、有限表达式原语、动态范围有效末尾与资源上限。
- 明确依赖影响检查粒度、语义版本/停用行为、模板指纹规则，以及自动期间的时区和跨月确认重验。

## 5. 验证与结论边界

遵守 [AGENTS](../AGENTS.md) 的针对性测试纪律，优先复用核心验收，不以用例数量替代业务验证。

| 范围 | 入口或方式 | 可证明的范围 |
|---|---|---|
| 环境 | npm run doctor | 只读环境与内存驱动检查 |
| 执行引擎 | npm run e2e | 临时工作区假数据的接入、查询、导出和边界 |
| 旧 authoring | npm run test:authoring / test:pi | 现有草稿发布及协议回归，不能代表新 Web 已完成 |
| CLI / 服务 / 分发 | npm run package:check | 实际 tarball 安装与相关入口，不等于所有平台支持 |
| 新 Web | 隔离工作区的关键交互与真实模板验收 | 配置、发布、异常处理、调用和下一期复用，随实现补充关键验收 |
| 文档 | git diff --check 与本地链接检查 | 一致性及链接有效，不证明运行功能完成 |

检查结论写在任务/PR，本文只保留能力状态和剩余交付，不追加开发流水账。
