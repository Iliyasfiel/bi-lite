## 0. 工程纪律（贯穿全程，live）

1. **e2e 是唯一门禁。** 每阶段收尾必须全量绿 —— 全量跑，不是只跑改动那一段。
2. **断言值必须来自独立算法。** 判例见 `AGENTS.md` §6.1（B4=765345 那个错值被写进断言后，测试反而成了 bug 的守卫）。每个新加的数字断言都要能指向"用另一条路算一遍"。
3. **接口全绿 ≠ 功能可用。** 判例见 `AGENTS.md` §6.2。带交互的功能交付前真走一遍人的路径（浏览器点击）。
4. **原地演进的纪律**（P5 等破坏性变更时全部适用）：一个库、一个门禁；破坏性变更**一次做完**（改 DDL + 改装载 + 改查询 + 改断言不跨阶段拆半）；每阶段全绿才继续；**改动前先 `git commit`**（没有第二份可回退副本）；生产库**重灌不写迁移脚本**（源 Excel 一直在手）。
5. **手动纪律：开 PR / 发版前，干净克隆跑一次** `git clone … && npm install && npm run fixtures && npm run e2e`。门禁要在别人的起点上跑才算数 —— 本机的 `data/`、夹具、缓存恰好能盖住"测试借了私有东西"这类洞（判例：第 19 阶段曾借生产规格，干净克隆必挂）。

## 1. 现状：功能与架构（已完成，506 项 e2e 断言钉着）

> 详规在 `需求与架构.md`，执行规约在 `AGENTS.md`；本节只给地图、判据与 e2e 锚点。

### 1.1 数据链路：着陆 → 接入 → 星型表

- **着陆层**（`src/land/`）：源文件 → `raw_file` / `raw_cell`，append-only。`file_hash` 幂等（同文件跑两次一格不重写）；`raw_source`（路径 → 最近一次着陆）让**源文件删了也能重放**；round-trip 与工作簿逐格一致。落库必须先着陆；干跑一次库都不写。
- **接入层**（`src/ingest/`）：宽表 / 长表同一条路（长表期数逐行不同是合法形状 `PERIOD_PER_ROW` warn；行键 = 行键列 + 期数）；日期格靠声明 `keys[].type: date`（只 1900 系统、序列号 <61 拒、1904 系统两处响亮拒绝）；两档主数据归并（铁律 16）；落库**事务化**（BEGIN/COMMIT + 进程内串行队列，并发落库全部成功且批次 id 两两不同）；跨批次默认 reject（`CONFLICT_WITH_EXISTING`）；源被删/路径漂移有守卫（生产规格的 `source:` 必须指稳定位置 —— `AGENTS.md` §7）。
- **目标表由声明决定**：接入规格 `target:`（缺省 `fact_finance`）只从 `models/*.yml` 声明过的事实表取；`TARGET_NOT_DECLARED` / `TARGET_NO_PERIOD_TYPE`。
- **旧长表路径零残留**（`src/import/` 目录已消失，`resolve.ts` 搬进 `src/ingest/`）；长表对拍基准冻结为 `test/expected/集团导出长表-960行.json`（判据来自旧路的一次独立执行，此后固化）。
- e2e：第 2–3 阶段（干跑/落库）、第 15 阶段（主数据对齐）、第 16–20 阶段（着陆/重放/顺序守卫/事务化/路径回放）、第 26–28 阶段（长表对拍/日期格/CLI 薄壳）。

### 1.2 声明式生成器（`src/gen/`）

- `models/*.yml` 是业务表（含历史侧表）的**唯一真相**：物理事实（列/类型/PK/DEFAULT）与语义事实（role/semantic/unit/引用）**同一份声明**。链路：YAML → IR（`metaOf()` 列契约投影）→ `bilite plan`（只读 diff）/ `bilite apply`（DDL + 契约 + `_model`/`_model_dep` 同一事务）。
- 四条验收（e2e 第 30 阶段）：**IR 是真抽象**（同一张表两种 YAML 写法，IR 逐字段相同）；**apply 幂等**（再 plan → 0 项变更）；**加列不重写数据**；**`_meta_columns` 不漂移**（META = `metaOf(loadModels())` 投影，与 `information_schema` 对拍）。
- 两条设计决定：**启动不自动做结构变更**（只空库引导 + 契约刷新；有变更响亮报告留给 `apply`）；**删列/改类型是阻塞项**，apply 见阻塞项整体不动 —— 半个落地比整体不动更难查。
- **聚合表（`kind: aggregate`，第五种模板）**：声明 `source`（必须是声明的 fact）+ `grain` + `measures`（v1 只认 sum），列由跨表投影（人不写列）；**口径与期数不许被聚合掉**（`MODEL_AGG_NONADDABLE`，铁律 8 前移到解析期）；`grain` 与源粒度同集合 → `MODEL_AGG_NOOP`（warn 也 fail-closed）。写路径只有 `CREATE OR REPLACE TABLE AS SELECT` 全量重算（删了能回来）：`plan` 只比列名集合、不一致即非阻塞 `rebuild-table`；落库同事务重建；`bilite rebuild` 手动重算（`rebuildAll()`，CLI 与落库共用 `executeRebuilds()`）。e2e 第 34 阶段 18 条断言（含独立 SQL 对拍与投毒恢复）。
- **桥接层（`kind: bridge` + 维度声明行 `rows:`，第六种模板）**：小维表与多对多映射写进 `models/*.yml`（git 即审计）；`sync.ts` 全量对齐（DELETE→INSERT 维先桥后，维行 id = `nameHash(name)` 派生、桥接行外键写名字落库解析成 id 错名整批拒、每公司权重和 ≠1 整批回滚）；带 rows 的维不许被 fact 引用（`MODEL_ROWS_OWNER_BAD`）；聚合 `via:` 穿桥 = SUM(amount × weight) 加权摊分，join 键自动推导恰一对、grain 留桥坐标（`MODEL_AGG_VIA_BAD`）。e2e 第 35 阶段 23 条断言（含守恒对拍与错名/权重负例）。
- `src/db/schema.ts` 只剩基础元数据 DDL；业务表 DDL 全部由声明生成。

### 1.3 事实表与维度

- **事实表两张在跑、一张声明样板**：`fact_finance`（财务口径体系）；`fact_business_line`（运营，**无口径列**、`business_line` 行内退化列进主键 —— 铁律 8：口径体系不同，不塞进财务表）；`fact_contract` 是 P2 第三事实表的**验收样板**（DDL 由声明长出、不改 `gen/`，暂无接入链路，e2e 仅用作 `via` 负例探针）。
- **SCD2 挂侧表**（`dim_*_hist`，PK `(id, valid_from)`，区间半开）：当前态维表不动 → 既有查询**结构性零回归**；生效日 = 期首日（绝不用 `now()`，否则重放得出不同历史）；`scdProblems()` 五类对拍两份表示；时点查询显式 `dimAsOf`；建维与首版历史同一事务。已知边界：事实行只记业务键，"按事实期自动取当时版"要写一次 as-of join（版本键进事实表是 P5 级切换，不做默认）。铁律 19。
- **查询侧目标表声明化**：报表规格顶层 `fact:` / 看板 `MetricsQuery.fact`（缺省 `fact_finance`），白名单校验 `FACT_UNKNOWN`；**维可用性判据唯一一份** `dimAvailableOn(dim, fact)`（compile/lint/query 共用，`DIMENSIONS` 六维含 `business_line`）：无口径表配口径轴 → `DIM_NOT_ON_FACT`，measures 带 `periodType` → `PERIOD_TYPE_NOT_ON_FACT`（静默忽略 = 写的人以为在起作用）。三入口（Web/MCP/CLI）注入 `declaredFactsOf()`。
- e2e：第 31 阶段（运营表接入）、第 32 阶段（查询侧声明化）、第 33 阶段（SCD2）。

### 1.4 规格引擎与语义层

- 报表规格（YAML）→ `compileBlock` → SQL → 两个 renderer：Excel 模板填充（xlsx-populate，原生 XML 补丁兜底版式）与 ECharts。
- **解析期挡住欠约束**（铁律 17，判据一份）：量纲维必须钉住；参数声明了没用即拒；口径名形近写错 `PERIODTYPE_UNKNOWN`（接入/报表两侧同源）；诊断一次给全。Web 边打字边诊断；agent 用 `lint_spec` 自己先撞一次墙。
- `queryMetrics`：受众分级（human/agent）挂在入口上；聚合反推防护（每格明细行数下限 3）；注入防护；`compileMetrics(mq, facts?)` 编译期拒未知表/无口径表。
- **语义自省 + 查询改写器**：`src/semantic/introspect.ts` 从 `models/*.yml` 同一投影推出每张表能查什么（度量/维引用/切片/口径列/谱系），纯函数零 DB、零新登记（架构 §7.1），随 `catalogDump().semantic` 导出；`src/semantic/rewrite.ts` 把业务形状（指标成员名 + 查询级口径）翻译成 `MetricsQuery`——只翻译不判，白名单/钉住判据仍只在 `compileMetrics` 一处；P5 的 selector/calculator 在改写器内部扩，调用方形状不变。
- e2e：第 4–11 阶段（编译/渲染/口径/安全/语义层/图表）、第 14 阶段（spec 校验防静默算错）、第 36 阶段（自省/改写器/catalog.semantic）。

### 1.5 三个入口（一个引擎、三个薄壳）

- **CLI `bilite`**（`src/cli.ts`，给人与脚本）：命令面走完 —— 引擎侧 `ingest lint|dry-run|run` · `render` · `query`；生成器侧 `plan` / `apply`；物料侧 `catalog dump|show` · `validate` · `skill export`；运维 `compact`。方案 A：CLI 自己开库（与 Web/MCP 同构，互斥由 DuckDB 单写者锁强制，占用即明确报错）。形状取自 DSH CLI：`parseCliArgs()` 纯数据、handler 惰性 import（`--help` 不加载原生依赖、不碰库）、stdout=结果 / stderr=日志与诊断、命令表自检（注册无 handler 启动即报错）、退出码由 `main()` 一处（e2e 才能进程内跑）。
- **Web**（`src/web/` + `server.ts`）：导入向导（上传 → 诊断 → 干跑 → 拍板 → 落库 → 归档，六路由全断言，含并发落库与归档可读）+ 看板查询 + 报表预览/导出 + 模板上传出 spec 草稿。**页面不写判据**，全走服务端（铁律 17）；`source:` 由人点按钮改。
- **MCP**（`src/mcp/`）：12 工具零依赖 stdio；e2e 用**真实 MCP 客户端**验收，每个工具都被真调用（漏了点名）。
- **安全不变式（CLI 侧三件事）**：① 受众按入口钉死 —— `bilite query` 固定 human，无任何开关；② agent 侧物料（SKILL.md、`skill export` 产物）**不许出现** CLI 取数命令（e2e 断言钉着）；③ 残余风险写明：防的是**便利路径**不是物理隔离（agent 有 shell 本来就能绕开一切）。
- e2e：第 0.5/21/23/28 阶段（CLI）、第 12/25 阶段（Web HTTP 面）、第 13 阶段（MCP）。

### 1.6 运维件

- **Parquet 归档**：`exportParquet()` 短命只读实例 + 写完读回数一遍（`verify`）+ `reattach()` 拿回库锁；归档在 COMMIT 之后。
- **`bilite compact`**：`:memory:` 实例合并，不碰库锁（服务端跑着也能合）。三条纪律：逐 `batch_id` 对拍才删源；按大小挑候选且 ≥2 个才动；0 行残骸不删不并、单独报、退 1。
- **物料侧**：`catalog dump|show`（L1/L2/L3，零金额，目录过期 `CATALOG_STALE`，契约漂移不以成功退出）、`validate`（→ 建议改为）、`skill export`（与 `skills/bi-lite-ingest/SKILL.md` 对拍不漂）。`_ingest_batch` 不在导出里。
- **上传件只增不减**：可删的前提 = 已着陆（raw 里有）且无任何规格 `source:` 指向它；e2e 扫 `src/` 断言没有代码删上传件。
- e2e：第 22/24 阶段（catalog/skill）、第 29 阶段（compaction）。

### 3.1 P3 —— 五种模板铺开 + 语义层自省（agg_* / map_* / 语义自省已落，余项未开工）

- `map_*`（✅ 首对已落 —— `dim_business_line`（声明行）+ `map_org_bl`（含权重），`via:` 加权摊分 —— §1.2，2026-10-02 第 35 阶段）；`dim_statement_line` + `map_metric_stmt` 等消费方（按科目行出报表）出现时再落。
- `agg_*` 全量重建（DuckDB 无 matview，重建即满足"删了能回来"）。（✅ 已落 —— `rebuildTableSql()` + `bilite rebuild` + 落库同事务重建）
- ~~`sem_metric` / `sem_dim_ref` / `sem_lineage` / `sem_caliber` + 查询改写器；语义层自省~~（✅ 已落 —— **按架构 §7.1 判据走了自省路线，不建 `sem_*` 登记表**：`src/semantic/introspect.ts` 从声明推出每张表能查什么（度量/维引用/切片/口径列/谱系），随 `catalogDump().semantic` 导出；`src/semantic/rewrite.ts` 查询改写器（业务形状 → `MetricsQuery`，只翻译不判）—— 2026-10-04 第 36 阶段。P5 的 selector / calculator 在改写器内扩，调用方形状不变）

**验收**
- 新增第三种事实表（如 `fact_contract`）**不改 `gen/` 里任何文件**。
- **铁律 17 原样迁移**：量纲维必须被钉住；判据只能有一份。

**主要风险**：语义层长出第二份元数据。判据：**语义层只从 `_meta_columns` 自省，不新增登记表**（架构 §7.1）。

### 3.2 P5 —— 正交维度与口径二分（未开工 · **最高风险**）

**目标**：`period_type` 五值拆成三件（时间窗口实存 / scenario selector / calculator 语义层），`scenario` / `ccy` 入键，切换事实表。

**交付**
- `dim_scenario` / `dim_currency` / `fx_rate`。
- 口径二分（架构 §7.4 判据）：本年累计 / 去年同期累计 / 账面累计 → **时间窗口，实存**（含审计调整，累加不等，**不许派生**）；单月 → 粒度本身；**单月同比 → calculator，语义层算，不占事实表列**。

**对拍方案（原地演进下的唯一防线）**：把 `period_type` 列**留到 P5 收尾当独立算法** —— 旧路（直接 `WHERE period_type = …` 查列）与新路（scenario / 时间窗口 / calculator）数字一致，**期望值取自旧路**（不是新路自己跑一遍，否则重演 `AGENTS.md` §6.1 判例），一致才删列，重灌生产库。

**主要风险**：**口径拆解错**。全计划里唯一"错了不报错、数字还同量级"的地方（判例 `需求与架构.md` §7.2.1：返回 67283、真值 65198）。防线只有对拍 + 单一判据，没有第三条。

### 3.3 P6 —— 治理收口（未开工）

- `fact_provenance` 仲裁：同一 grain 多来源 → **默认整批拒绝并列出冲突行**，不静默翻倍；写 `replace` 声明才覆盖，且覆盖要让人看见。
- `_dq_result`：`not_null` / `unique` / 值域 / 跨表对账。
- 漂移检测：`_meta_columns` vs `information_schema` 不一致要能被发现，且在 apply **之前**就报。
- 权限收口：BI 不直连 `fact_finance`，只给语义层视图。

### 3.4 暂缓项（2026-10-02 用户拍板，"先不做"不是砍掉）

- **profile 导出**（架构 §8.5 的复用单位：语义快照 + 模板集合 + 版本钉，不含事实数据）—— 用户原话"先不做，记一笔就行"。模板单独 portable 没有意义，要搬就是整套语义连同模板一起搬。落地底座已备：`catalogDump()`（`src/meta/catalog.ts`）与 `masterCatalog()`（`src/ingest/master.ts`），profile 应以它们为底，**不新增取数出口**。
- **CSV 接入**（架构 §8.1：格网与绑定关系不变，只换介质）—— 用户原话"先不做，这个是纯增量"。做的时候不产生第二份判据。
