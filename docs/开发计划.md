# 开发状态与计划

需求、术语和目标架构见 [需求与架构](需求与架构.md)；用户操作见 [README](../README.md)，
人工验收见 [规格制定与入库测试指引](规格制定与入库测试指引.md)。
本文记录当前工作区实现和下一步完成条件，不将离线替身通过等同于真实业务交付。

## 1. 当前判断

**规格制定仍处于开发验证阶段，语义读取架构未完成，尚未通过真实供应商到业务报表的完整验收。**
`bilite spec <Excel路径>` 已有连续入口、候选校验和确认发布实现；
CLI 是人机交互层，内部模型通过 pi 工具调用共享服务，不执行 CLI 子进程。
当前只向模型预加载部分声明元数据，不能据此认定 agent 已具备完整语义理解能力。

| 范围 | 当前实现 | 验证与缺口 |
|---|---|---|
| 本地执行引擎 | 长表/宽表/网格接入、主数据对齐、raw/stg/事实、批次快照与重放；参数查询和模板导出 | 既有人工链路保留；新制定规格的业务闭环待验 |
| 文件检查 | 全工作簿扫描、空白结构投影；隐藏页参与检查，公式正文不进入模型 | 结构边界有离线验收；图片、批注、嵌入对象不属于语义脱敏覆盖范围 |
| 共享任务 | 方向、修订、草稿、连续消息和工具回执、租约、预算、取消与恢复 | 离线关键节点已验收；不能代替供应商连续多轮稳定性验证 |
| 内置 harness | 当前方向的 YAML 契约、可校验最小示例、模型/指标声明格式；一个提案工具 | 示例如语法说明使用，不是默认业务声明；真实模型遵循契约的完整回归待验 |
| 声明语义 | 从 models/、metrics/ 解析元数据，每轮注入受控快照 | 指标公式仅有 hasCalculation，无正文与依赖明细；没有按需语义读取工具 |
| 候选校验 | 在内存叠加候选声明，校验规格；导出编译可注入候选指标，检查填充区与公式碰撞 | 引擎校验与模型看到的语义不是同一完整视图；失败候选可修订性仍需真实验证 |
| 确认发布 | 本地明确确认、计划绑定、工作区锁、多文件提交记录、读取屏障、恢复与幂等 | 两方向关键节点有离线验收；真实供应商生成后由人确认保存的整条流程待验 |
| CLI / Web | spec 单入口已有实现；Web 保留原有人工接入/导出 | Web 尚未接入统一制定服务；CLI 入口存在不等于共享引擎架构已完成 |
| 分发 | 已制作实际 tarball，并仅在独立本地测试区安装、做入口检查 | 本轮未运行完整 package:check / e2e，不扩大既有平台支持结论 |
| 外部 agent / MCP / skill | 保留旧结构与元数据入口，数据试运行和接入交接本机用户 | 不是内置助手完整语义服务的替代品；退役时机待统一流程验收后确定 |

真实 DeepSeek 已进行多轮结构澄清与提案尝试；已确认语义不足和契约/诊断可用性问题，
因此不能写为“尚未调用真实模型”，也不能写为“真实规格制定已通过”。
当前修补有离线回归，最新版本仍需真实供应商复验；业务入库、出表和 Excel 重算未验收。

## 2. 当前语义读取与目标的差距

当前路径：

```text
models/ + metrics/ → 本地解析 → 受控 semantic JSON → 每轮系统上下文
模型提案 → 本地候选声明覆盖 → 静态校验/查询编译 → 摘要与差异 → 本机用户确认发布
```

| 问题 | 当前状态 | 目标与待定事项 |
|---|---|---|
| 完整语义 | 模型可见表、列、关联、单位、窗口、默认场景/币种、指标身份与别名 | 明确完整声明语义的范围，覆盖公式、依赖、适用事实表及口径约束；不包含业务金额 |
| 按需读取 | 仅预加载快照，模型工具只有 submit_authoring_proposal | 设计可检索、可解释的只读语义契约；工具形态、查询粒度与返回字段尚未定稿 |
| 提案表示 | 工具参数有类型约束，规格正文仍是自由 YAML 字符串，本地再解析校验 | 明确语义提案、布局与 YAML 生成的职责；文本契约和示例不能代替统一的语义结构定义 |
| 候选视图 | 本地验证器使用覆盖后的声明；模型 semantic 仍来自已发布工作区，候选声明主要靠历史提案回看 | 模型读取、候选校验和最终审阅引用同一候选语义版本，区分已发布基线与未发布改动 |
| 版本与失效 | 草稿、声明指纹和发布计划已有绑定；提案仍要求模型回传版本号 | 核清语义读取版本与任务/草稿/发布的统一绑定，以及变更、过期和并发处理；避免靠模型记旧编号 |
| 语义解释与确认 | 本地生成规格摘要和文件差异 | 让用户能核对公式、窗口、单位与主体范围的依据；说明哪些是声明、哪些是用户确认、哪些仍未决 |
| 上下文增长 | 完整历史和提案回执保留，达到本地字符预算即停止；无自动压缩 | 明确预加载与按需读取的分工、资源上限、恢复方式；不靠反复调高阈值替代语义接口设计 |

语义架构需要先设计再实现。本轮仅整理状态，不将某个 CLI/MCP 命令、工具名称或自动压缩方案直接定为最终架构。
共享语义服务与交互入口分离；未来 CLI/Web 可复用同一契约，模型不应通过运行 CLI、SQL 或读取业务库来补齐语义。

## 3. 下一步交付顺序

| 顺序 | 交付内容 | 放行条件 |
|---|---|---|
| 1 | 明确只读语义契约及候选视图 | 覆盖既有公式、依赖、单位、窗口与候选声明；读取和校验语义一致；输入/输出、版本、权限与上限明确 |
| 2 | 将语义契约接入内置助手 | 在隔离工作区验证既有语义读取、候选修订和失效处理；模型无需向用户索要引擎 schema 或堆栈 |
| 3 | 两方向真实 CLI 制定与确认 | 从用户选定的空白样表开始，完成澄清、提案、修订、审阅、确认保存与恢复；不依赖手抄 YAML 或版本号 |
| 4 | 新规格的业务报表闭环 | 本机用户使用新规格试运行、确认主数据、入库、重放并导出；核对业务数值、窗口和模板保真 |
| 5 | 分发与 Web | 补齐实际安装包和目标平台验收，再接 Web 的同一制定服务；HTTP 权限和确认边界独立验收 |

第 3、4 步以 [18期经营测试](18期经营测试.md) 的显式选择材料为代表性验收；
接入方向使用同源表几何的无数据样表，导出方向使用报送空白模板，不能混用布局。
已有手写 YAML 只作语义参照，不能复制后宣称是新流程生成。

真实验收至少核对：主体/合并范围、复合行键、金额与比率单位、累计与单月窗口、
分离取数区、公式保护、缺基数与跨年参数。现有样例的相对增长率和新任务另行确认的百分点差属于不同口径，
不得把新对话决定自动写成旧样例已验收结果。

## 4. 运行边界与维护

- 制定只使用空白结构、用户文字和 YAML 声明，不加载 DuckDB、不查询实存主数据、不执行 apply、接入或报表取数。
- 确认发布只由本地明确操作触发，普通对话中的“好的”和模型自述都不能发布；成功以文件提交与核验为准。
- 内置契约提供语法依据，错误结构返回字段诊断；不进入摘要或编译后再以内部异常代替诊断。
- 既有人工接入/导出保留；开发 reset 仅用于独立测试区，不清空用户测试目录或数据库。
- 本机供应商配置、缓存、代理、安装位置和密钥不进入版本库；不自动全局安装或修改用户配置。

pi 依赖锁定 1.3.0。当前默认请求预算为超时 120 秒、重试 1 次、重试等待上限 5 秒、输出 8192 token、
单次运行最多 6 个模型轮次、任务累计最多 24 次运行（传输重试另受上限约束）。
本地上下文默认 1000000 字符，可用 maxPromptChars 显式调整；它不是供应商 token 窗口，
SDK 模型描述中的窗口元数据也不代表已核验供应商实际容量。
预览、发送前检查与续轮共用计数，纳入系统提示、工具声明、消息和工具回执，排除仅本地使用的诊断副本、用量和时间信息。
发送前超限不占运行次数；同次运行在工具回执后仍可能增长并触及上限。

| 范围 | 入口 | 可证明的范围 |
|---|---|---|
| 环境 | npm run doctor | 只读环境检查，原生驱动仅在内存启动 |
